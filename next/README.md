## 当前V3规划配置操作

1. 在“项目与研究→研究任务”新建或继续一个“规划”任务。规划第三步保持“现状诊断”。
2. “规划与优化→规划目标/约束库/决策变量”可分别独立新建，不要求先建立规划问题。名称搜索、排序、分页读取服务端真实记录。
3. 目标选择单目标、加权多目标或多目标权衡；仅加权模式填写权重。当前可配置四项加性目标度量，其他指标/目标并未因此全部实现。
4. 约束只填写必要业务上限、单位和适用依据；系统不提供假政策阈值。决策模板明确允许改变哪些单元，当前三种模板仅为二元选择，不代表完整多用途土地配置。
5. 修改后等待“已保存”。保存失败或冲突时编辑保留；冲突区同时显示原值、服务器当前值和本地修改，可明确选用一方。只在服务器确认后显示已保存。
6. “发布配置版本”校验并固定版本。发布不是运行审批，也不会修改当前任务。点击某个版本的“应用此版本”，才更新当前规划研究的引用。没有活动规划任务时不会显示应用按钮。
7. 回到右侧“规划目标”或“约束与决策变量”，可核对固定配置或选择其他已发布版本；新版本发布不自动替换已有引用。历史成果不被改写。
8. **完整现状诊断、规划问题编译、候选运行与再评价尚未接通**。此时“预检并执行”明确报告工程缺项；不能将配置发布算作规划完成，也无需补一份旧版优化方法来绕过。

规划单元准备：将分区矢量或已可靠定位的候选点加入规划任务，在右侧“准备与对齐”点击“生成规划单元”。只有多个输入候选时才需要选择来源；无需先填写评价方法。作业完成后中央显示本次单元地图，点击要素查看面积和原始字段，工具条可调整样式、查看完整属性及导出。点单元没有面积值。此产物仅为规划准备，不能作为规划最优解、现状诊断或业务批准；原始字段名称不自动被解释为成本、收益或政策约束。

## 启动与独立初始化

需要Python 3.12、Node.js及npm。下面从仓库根目录执行。

首次安装新版独立依赖：

```sh
python3.12 -m venv next/.venv
next/.venv/bin/python -m pip install -r next/requirements.lock
npm --prefix next/web ci --ignore-scripts
npm --prefix next/web run build
```

现有新版研究空间已初始化，启动它（端口被占用会退出，不替换已有服务）：

```sh
next/.venv/bin/python next/scripts/serve.py --config next/.state/settings.json --port 58010
```

仅当需要另建干净研究空间时执行，名称必须未使用：

```sh
next/.venv/bin/python next/scripts/bootstrap.py --name my-research --local-source /Users/quanyiming/Projects/data_quan
next/.venv/bin/python next/scripts/serve.py --config next/.state/my-research/settings.json --port 58012
```

独立初始化使用新SQLite数据库和新对象目录；当前58010研发空间使用独立PostgreSQL。初始化不读取旧`.env`，也不导入旧审批资格。首次生成的管理员账号、随机密码和项目写在对应目录的`settings-access.json`，该文件仅本机用户可读，请勿提交或共享。保留整个`.state/<名称>`可恢复该研究空间；不要删除其中数据库、对象或访问文件。

启动器同时运行API和worker；正常退出时停止接新任务，worker完成正在进行的操作后退出。启动失败会报告实际错误。原模型执行另需Docker和经过实际数值核验的运行包清单；新空间不会自动获得旧项目的执行批准。

## 使用现有功能

1. **选择当前项目**：顶栏控制后续任务、资料和认可依据。切换项只包含本人有权访问的项目。系统管理员管理账号；项目负责人维护成员和项目权限。只读成员不能提交编辑或运行。
2. **开始任务**：填写可辨认的任务名称并选目的。资料检查用于了解内容；实体任务读取真实几何；时间适配使用真实时间轴和区间；综合评价与空间优化采用已认可的方法；投影寻踪任务使用给定原始算法。组合工作流和科研验证的完整产品链路仍在研发，不能视为已交付。
3. **添加资料**：一次可选多个文件，系统自动识别实际字节。每项独立显示成功或失败；刷新后可继续处理失败项。原始资料不被改写。受控目录入口由系统管理员授权项目，进入后搜索、选择实际文件并提交批次；普通账号不会看到未授权路径。负责人撤销授权后会阻止维护者后续接入，并在文件登记前复核；已登记资产和原文件保留。系统管理员仍有配置范围内的管理访问资格。
4. **核对自动读取结果**：资料卡展开“查看自动读取的内容与质量”，查看格式、声明版本、字段类型、原始单位、问题及最多20行预览。缺值不会显示成0，字符串标识的前导零保留。多个表或图层需要选择实际用于本任务的对象，不默取第一层。地图预览使用实际栅格并加载在线底图；预览极值和像元数不是全图统计。
5. **补充来源声明**：展开“集中补充或修订声明”，仅填写实际已知的来源、使用限制、年份与依据。空项保持未知，2022只代表年份而非人为补出的日期区间。认可声明限定当前实际文件，后续重复选用该文件自动沿用；新文件不继承旧观测年份。
6. **补充变量定义**：自动映射表中，“本次用途”控制变量在当前任务中的角色；“科学含义”是明确指标定义，“单位”是有依据的科学单位，“支撑”描述点、区间、网格或管理单元。来源文件有单位时，不能用不兼容量纲覆盖。“响应变量”必须来自真实业务目标，系统不代猜。
7. **认可并复用定义**：有已知定义后展开“将已知指标定义保存为项目依据”，填写依据并明确范围。默认仅当前文件；确认属于同一类资料后可选“本项目后续同名、同结构资料”。负责人保存并认可，其余编辑者提交待认可。新批次重新读事实和创建绑定，符合范围才沿用有效定义。响应变量、年份、方法权重不随字典复制。不同含义的同名字段不能强行合并。
8. **维护与采用方法**：“方法与依据”中维护评价指标、方向、固定参考上下限、单位和适用权重，或优化的成本、收益、面积、保护准入、预算等。维护者保存草稿，负责人认可版本；分析任务直接选择认可方法，不录入矩阵JSON或重录已有候选单元。没有依据的值留空，不能用默认0代替成本。
9. **预检并执行**：点击后冻结当前资料、任务与方法版本。预检只要求本任务实际使用的必要条件；失败会说明相关缺口。运行通过worker产生实际结果，可查看表格、地图与完整下载。原包项目批准由负责人操作，与普通选择模型分开。
10. **保存与恢复**：只有收到服务器确认才显示“已保存到服务器”。返回、刷新、关闭重开恢复已保存版本；请求失败时保留当前编辑并显示重试。并发修改不同独立信息可自动合并，同一科学配置整组核对。选择保留本地或服务器版本再保存。未收到保存确认时不要强制关闭窗口；未送达服务器的最后输入不能宣称已持久化。
11. **查看成果**：实体结果在“完整实体属性”表分页查看，数字0、布尔否与缺值分开显示。点击“在地图定位”可定位对应实体；点选地图返回相应表格页。大集合地图最多显示5000个实体（包含当前选择），表格与GeoJSON下载保留全部实体。空间优化成果包包含全部候选单元的CSVW表：入选、保护准入、成本、面积等保留原值，无可行解时选择列为空。

12. **核对运行依据**：工程成功表示程序完成，并不表示方法或业务结论已获科学认可。成果JSON包含固定输入与版本依据；完整包包含实际数值、适用标准文件和来源。真实全域推理与采样训练范围分别记录，采样结果不冒充全图。

## CSVW标准包的实际支持范围

依据[W3C CSVW元数据规范（2015）](https://www.w3.org/TR/2015/REC-tabular-metadata-20151217/)，目前支持ZIP内的CSVW表/表组元数据和相对路径实际CSV：自动识别、标题与列数校验、字符串/布尔/常用数值类型、声明缺值、单列/复合主键校验、方言、前导零、数值小数符，以及实际评价和结果CSVW重新导入。单表主键能自动成为观测身份；多表必须选择适用表。原包可完整下载。

边界：完整校验每表25万行、CSV解析256MiB；这与2GiB接入上限是不同预算。日期自定义格式、外键、虚拟列等尚未完成的语义会标记并阻断相关计算，不能因文件已登记而称全部标准支持。外部URL不被自动读取；独立元数据缺少实际表时不能执行计算。十进制定点值以文本保留精度，进入现有数值方法后按其浮点精度计算。原始字节始终保留。

## 标准任务接口的实际支持范围

供集成客户端使用，普通用户仍在任务工作台操作，无需选择协议或填写内部标识。服务入口为`/api/ogc/1.0/`，依据[OGC API Processes Part 1 Core 1.0](https://docs.ogc.org/is/18-062r2/18-062r2.html)提供已实现子集：发现、处理描述、分页运行状态、异步实际执行、失败说明、取消及结果引用。仍需现有会话，写请求携带会话的CSRF验证。不会自动公开发布，也不访问调用者提供的外部URL。

处理输入是当前项目已保存任务的固定版本，使用标准qualified JSON对象：`inputs.task.value`包含`id`与`revision`，`inputs.task.mediaType`为`application/json`；明确`response: document`，结果仅按reference返回。实际预检、权限、认可资格、计算与来源清单复用同一执行器，不建立第二套算法。调用方可提供`Idempotency-Key`，省略时同任务同版本自动去重。

当前不支持raw/value返回、任意URL输入、回调与全部作业过滤参数，明确报错。排队取消返回dismissed；正在执行的取消返回202，直到执行器确认才变为dismissed。已完成记录不可通过DELETE删除。由于这些边界与未执行完整OGC ATS，`conformsTo`为空，不宣称Core/Dismiss完整符合或认证。30份官方Schema及哈希保存在测试夹具中；正向结构校验、真实执行与自有接口数值/来源一致、权限、失败和取消均有测试。

### 时间适配

新建“时间适配”任务后上传NetCDF。单一适用变量、原始统计方法和单位会自动带入；只填写目标日期，系统保存到服务器后可关闭重开。日期按文件日历解释，例如360_day允许2月30日，不能当公历使用。

区间均值、累积、最小和最大要求完整原区间及对应cell_methods，不截断区间、不跳过缺测。点观测可选择最近邻或线性插值；非原始时刻必须给出适配依据，最近邻还需容差，等距时明确选择方向。单位只允许科学上相容的转换。预检说明具体问题，修正后直接重试。

执行后同页显示数值与单位、日历、目标范围、观测数量和适配依据；下载保留完整JSON及CSVW表，日期作为带日历说明的文字保留。当前支持CF1.7—1.12的一维时间子集，复杂cell_methods、气候平均和多维处理尚未完成。浏览器工程用例实测仅任务名与两个日期3次填写，目的与文件2次选择；这不是真实海岸业务结论。

### 成果比较与协同审核

1. 在当前项目新建“成果比较”任务。列表是本项目实际执行成功的评价、优化和时间适配成果；名称后的版本是执行时的任务版本，时间是提交时间。列表有真实总数和分页，翻页不会清除已选成果。其他模型类型的可比性规则仍在研发。
2. 在两条不同运行上分别点“基准”和“对照”圆点。上方一直显示已选名称；无需重新上传文件、重填指标或复制ID。选择自动保存，收到“已保存到服务器”后刷新或关闭重开可恢复。
3. 点“核对并比较”。系统核对原资料哈希、图层、变量含义、单位、支撑及科学定义版本。评价还核对方法、标准化区间和方向；时间适配核对原日历、区间、来源观测及适配依据。相容的参考单位自动转换并留痕。来源或基准不同、未知单位、缺失/重复标识、不可行优化会说明原因，不产生假差值。不会把簇编号当风险评分。
4. 结果中“基准”和“对照”是按原字符串标识对齐的真实值，“差异”为对照减基准；数字0不是缺测。优化显示“新增选择／取消选择／选择未变”，并不代表批准土地调整。评价权重变化只解释为同资料、同方法、同基准下的敏感性，不解释为年份变化或政策优劣。
5. 逐项表每页25条，底部显示实际数量。“下载完整成果包”含全部比较行CSVW、完整比较JSON、两份校验过哈希的原始成果JSON及来源说明。原成果上的“下载原成果”保留历史版本，不触发重算。当前比较读取上限为每份成果256MiB、100000行；超限明确阻断比较，原成果仍可下载。
6. 同页“协同意见与技术审核”对应当前查看的运行。可编辑成员填写“意见内容”，选择科研／管理／公众讨论视角后“发布意见”。讨论视角仅说明意见立场，不赋予账号权限；查看者仍只读。各账号意见草稿分别保存在服务器，未发布内容不进入他人的意见列表。离页前自动保存，刷新恢复；冲突时同时保留本地与服务器文字，核对后选择采用哪份。失败可重试，不必重写。
7. 项目负责人可使用同一已保存文字作为技术审核说明，点击“记录技术核对通过”或“要求修改”。审核历史保留作者、时间和顺序；并发审核不会覆盖他人的记录。意见／审核提交重试不会重复新增。普通分析成员不能审核，查看者不能发布或审核。
8. “全部审核记录”可展开分页查看。切换运行会切换对应意见与审核；修改方案后新运行从“尚未审核”开始，不继承旧结论。技术核对不会将成果改成“正式业务有效”，也不代替真实政策决定。

本次浏览器记录：成果比较自身为1次名称填写、3次选择（目的及两项成果）、无重复确认；协同例为2次文字填写、1次视角选择，导航/刷新恢复未重填。前置成果通过实际文件上传和worker准备，单独列明，不计入上述比较阶段成本；这些测量不能宣称为整条业务链路成本。

浏览器验收使用已安装完整Chromium无头模式（`channel: chromium`）。本机精简headless-shell在独立寿命试验中约30.7秒自行退出；失败轨迹与试验结果保留，不以分批跳过代替完整验收。新环境首次测试可安装：`next/web/node_modules/.bin/playwright install chromium`。

成果比较中，偏移温标的差值明确记录增量单位，例如摄氏温差为`delta_degree_Celsius`；CSVW中的`unit`与`difference_unit`分别说明原值和差值，不把温差按绝对温度转换。


## 数据资源：先接入和查看，再开展分析

进入顶部“数据资源”，选择“导入并查看资料”。可多选；无需任务名称、边界、科学定义或模型。服务器默认每段8MiB校验，原件受管后第一份成功资料自动打开；后续文件不抢地图视口。搜索、排序及20项分页都由服务器执行。目录选择仅改变查看对象，不把文件加入科研计算。

地图按原件定位显示实际栅格。色带来自注明数量的固定显示样本，不是全图统计；缩放按需读取窗口，不向浏览器发送全图像元。显示/透明度/波段不改变原件或分析。点图可核对源行列、存储值、scale/offset后值、掩膜状态与原件hash。单位未知就显示未声明，不影响普通查看。NoData与范围外分别显示；缺定位时显示非地理图像并说明原因，不套默认坐标系。手机用“资料目录 / 地图与详情”切换。

选择资料和用户拖动后的地图位置保存至当前账号的项目视图。出现“个人视图已保存”才代表服务器确认；刷新、关闭重开后直接恢复，不重选原件。另一窗口冲突保留当前本地显示并提示刷新核对，不覆盖服务器视图。

上传中断：展开“未完成接入”，重选同名、同大小的原文件。客户端先逐一核对已保存分段的内容，再补传缺段；错误文件不会混入旧上传。所有段已保存时直接“继续提交”，无需重传。放弃只删除本会话暂存，不删原件或已登记资产。某一文件失败不会回滚其他成功资料。当前会话接收上限与磁盘预算由服务器执行。

当前这一路径只完成单活动栅格显示，任务页原接入和多层矢量/RGB尚待统一；不是全部I02/I03完成。原文件的外部.ovr/.aux.xml未随单文件上传，受管显示不依赖这些概览；需要伴随文件语义的自动分组继续研发。完整进度见acceptance.json中I01—I11及A01—A52。

实现采用[Rasterio的窗口重投影机制](https://rasterio.readthedocs.io/en/stable/topics/virtual-warping.html)，显示投影不改科学网格。真实影像点查与读原文件对照、三视口截图、分段中断证据见artifacts/catalog-gate-browser-evidence/；性能测量条件见artifacts/catalog-render-measurement.json。视觉修改前1440截图误捕获登录中状态，未用作资料库改造证据。

### 任务内自动查看与资产身份

任务添加或复用资料后，会在统一资料列表和查看区自动打开；栅格无需再点击预览。显示波段、原生点查、显隐和透明度不改变分析绑定；位置与显示状态按账号、任务分别保存在服务器。刷新可恢复，冲突时先核对并读取服务器视图；不将未收到回执的更改标成已保存。资料复用支持服务器搜索与分页。

相同字节再次作为新资料接入，会有独立名称和资产身份，底层文件可复用；同一上传/批次的网络重试保持同一身份。升级已有next库保留资产ID及引用，SQLite会先在私有storage/schema-backups保留快照。旧生产库不参与。

当前界面尚未达到完整分组侧栏、多层工作台和全部科研图件要求；当前验证范围与未完成项见STATE.md和acceptance.json。task-view-browser-final为本轮18项真实浏览器证据；之前失败轨迹另存，不能用旧PASS代替新验收。

## 专业工作台：当前第一条真实空间链路

独立版任务书是本轮唯一开发基线；以下只说明已接入的链路，其余全量能力仍按验收矩阵研发。

1. 进入**研究工作台**，确认顶栏项目，使用**导入并查看资料**选择原始文件。可靠定位的TIFF接入后自动定位并显示，不要求先创建任务、画边界、填科学定义或选模型。分段接入的进度由服务器确认；失败项可恢复。
2. 左侧目录的**查找资料**搜索全项目文件名、显示名称、说明和标签；中文输入完成后延迟300ms查询，回车立即查询。**分类**过滤实际格式，**排序**选择接入时间、名称或大小，底部分页显示服务端实际总数。当前每页20项。
3. 点击名称查看原件；点击**修改**可修改显示名称、说明及逗号分隔标签。原始文件名、字节、科学版本和已冻结运行不改动。另一窗口已保存时会报告版本冲突，不覆盖对方修改。
4. 勾选需要的记录后选择**回收所选**。影响预览列出固定记录及引用；确认时重新检查权限、版本和运行。**回收筛选全部**会冻结当前整个筛选结果，之后新增的匹配资料不会混入。失败项逐条说明，成功项保留。**范围 → 回收站**可选择并恢复。回收只是逻辑状态，原件和历史成果仍保留；运行中的资料禁止回收，新分析不得使用已回收输入。本轮没有开放永久删除。
5. 地图的**显示数据层**、**不透明度**和**定位本层**只改变个人显示。点击地图读取原生像元行列、原值、比例偏移、有效性与来源；显示采样的统计范围明确标注，不冒充全域统计。无可信定位的资料仍可读取原始信息，但不猜测位置。
6. 栅格查看区选择**生成有效覆盖**，系统沿用当前资料、波段和项目，并自动命名、保存空间任务。进入任务后选择**预检并执行**；无需再选择资料或填写内部ID。工具逐块计算整个原生网格的有效掩膜，输出1为源资料有效、0为无效；有效的零值和负数不会被丢弃。这是有效覆盖结果，不是地类、海岸线或生态评价。
7. 运行完成后自动显示**本次实际空间成果**，原始输入不会冒充结果。图层、点查及下载绑定同一运行；实际全域统计在成果详情/统计视图查看。**下载实际成果**得到完整GeoTIFF，**下载完整成果包**包括固定输入和计算配置的来源记录。成果视图由服务器为当前账号保存，只有收到保存确认才显示已保存。手机默认打开主视图，可切换**配置与运行**；侧栏菜单支持Esc关闭并返回焦点。

目前矢量的全图层发现、分页原生属性与定位校验已具备后端测试，新的矢量查看界面尚未接完。完整业务分组导航、其余资源管理目录、面板拖动、年鉴空间化、AHP/评价型PP等必选能力尚未完成；不能将本链路的通过当作全量交付。

## 当前研究内容面板与八步入口

左侧使用**图层 / 输入 n / 运行 n**。图层勾选只控制显示，名称查看详情，更多菜单可定位、设置样式、查看来源、下载或移出地图。输入列出当前草稿绑定，**添加**提供资料库、文件上传和已授权来源；查看参考资料不会加入计算。移除输入先核对影响，原件和历史保留。运行按实际记录分页，点击查看固定版本，完整ID在详情。

最右侧依次为**资料、对齐、落图、指标、标化、权重、综合、验证**。悬停或键盘聚焦查看完整名称和状态，点击只打开对应面板，不自动计算。步骤、详情、样式和点查互斥，Esc返回触发位置；历史配置只读。

地图图例默认关闭，在**样式 → 显示地图图例**开启。紧凑图例只对应活动可见图层，预览样本值域不代表全域统计。工具条保留“工程结果 · 待验证”、加载/显示错误与重试；顶部“已保存”由服务器确认，保存失败/冲突明确显示。保存草稿不代表历史成果已重算。
