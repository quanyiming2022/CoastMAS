# CoastMAS 高效率、低 Token 与高代码质量执行规范

版本：EQ-1.0｜日期：2026-09-20｜性质：原《Codex 单任务研发总任务书》的明确补充。

本文件是新增工程要求，不是原资料已经实现能力的证明。目标是在原有完整功能范围内减少重复工作、上下文浪费、无效模型调用和返工；不以代码行数少、服务数量多或测试数量大代表质量。

## 1. 适用范围与明确覆盖事项

原任务书全部必选功能、两个核心工具、三个演示场景、动态评价、协同与空间优化示范、独立部署和 GeoAI 可选接口继续有效。不新增需要用户逐阶段确认的流程。

本次明确修改以下执行口径，其他要求不变：

| 原位置 | 本次执行口径 |
|---|---|
| 开头及第 76 节“一次完成” | 一次明确委托、内部连续实现与验证、统一交付；不是一次代码生成，也不是保证平台不会中断。不要例行等待阶段命令，权限和破坏性操作的必要授权仍保留。 |
| 第 4、5、69 节架构与选型 | 逻辑模块不强制拆微服务。新工程默认模块化单体 API＋独立计算 worker；知识图谱默认 PostgreSQL 关系表＋NetworkX，保留 KnowledgeGraphService。只有有实际需求和证据才额外部署 Neo4j。若已有稳定实现，不为换选型重写。 |
| 第 45 节表清单 | 清单作为必须覆盖的领域对象，不机械要求每个静态属性独占一表；可合理使用 JSONB 保存有版本的契约，但权限、版本、依赖、查询索引和引用完整性必须可验。记录实际映射，不丢字段和功能。 |
| 第 30、51 节角色名称 | 统一权限真源；PUBLIC 是公开参与者角色或受限 VIEWER 配置，能力映射写清，不能存在两套互相矛盾的鉴权规则。 |
| 第 56 节性能 | 保留原 P95 目标，但必须指定机器、样本规模、并发、冷热缓存、测量边界及错误率；无测量不宣称达标。 |
| 第 62 节 migration down | 只允许在本项目临时测试数据库验证升级—降级—升级；不得对用户已有数据库执行破坏性降级。 |
| 第 67 节代码关键词禁令 | 禁止核心必选链路空实现和伪完成，不通过全文搜索 pass/NotImplemented 来误判合法抽象类、协议和明确的不支持状态。 |
| 第 67 节“API 存在必须有 UI” | 必选用户操作必须有可用界面；内部 worker、健康检查、认证回调和机器集成端点不要求虚造界面。 |
| 第 71 节 Git | 交付应有明确 commit 和差异清单；不得删除、回滚或顺手提交用户已有修改来制造干净状态。 |
| 第 43、68、72 节科研实验与验收 | Mock、回放、规则降级、真实外部 LLM/模型实验分开计数；缺凭证或真实模型时标记 NOT_RUN/BLOCKED。缺失必选证据不得宣布全部完成。 |

质量优先顺序：科学真实性与安全 > 功能正确与数据完整 > 可维护与可复现 > 执行效率 > 可避免的 token 开销。

## 2. 一次委托的内部执行机制

先做一次有针对性的环境检查：项目目录与现有修改、Python/Node/容器可用性、数据库连接、网络与模型凭证可用状态；只记录“是否可用”，不输出密钥值。不得因一次检查失败无限重试，也不得盲目安装大量替代技术栈。

首次按章节阅读完整任务书，建立 `docs/requirements-traceability.csv`。字段至少为 `requirement_id, source_section, implementation_path, verification_command, evidence_path, status, blocker`。原 1—76 节和 Definition of Done 必须全部映射；其中一个章节包含多项能力时拆成稳定子编号。

实现依赖顺序由 Codex 内部安排。每个内部工作单元必须产生可验证的真实行为，而不只是页面壳或数据库表。典型循环为：明确契约与用例 → 写可复现测试 → 最小完整实现 → 跑相关测试 → 检查差异 → 保存证据。不要先生成整个前端再临时猜测后端接口。

维护一个短 `docs/STATE.md`，记录当前 commit/工作树、已验证能力、正在修改的文件、未解决阻塞、下一项明确动作及测试证据位置。目标不超过约 100 行；只在形成可复用结果或重要决策后更新，不逐工具写流水账。

重复失败两次仍未解释原因时，停止同样的盲试，建立最小复现，检查环境、输入、异常链和依赖版本。次数是诊断触发点，不是允许放弃功能的上限。

若平台硬限制导致中断，保存工作状态及剩余必选项；恢复后沿原任务继续，而不是重新规划或把任务伪装成完成。没有工具支持时不得声称正在后台继续运行。

## 3. 控制 Codex 开发过程的上下文与输出

### 3.1 读取策略

完整任务书只做首次需求梳理；后续从章节索引、相关符号、调用方、测试与 Git diff 定位。检索目标明确后读足够上下文，不为了少读而猜接口。相关实现变化或记忆不可靠时应重新核对，不能把“少读取”变成禁止核验。

默认排除 `.git/objects`、依赖目录、虚拟环境、构建产物、模型权重、栅格原始二进制及长日志。涉及锁文件和生成代码时查看必要差异，不把整个文件转储到对话。禁止用全仓递归 cat 代替定位。

将原始命令日志保存在 `artifacts/logs/`；工具输出优先返回命令、退出码、测试摘要和最相关的失败片段，需要时再查原日志。使用管道记录日志不得掩盖原命令失败退出码。不要只用 tail 的成功退出码判断测试成功。

### 3.2 文档与生成

短规则放 AGENTS.md，完整要求放 docs；不把整份任务书复制到每个模块、子代理和聊天回合。已有准确的设计决策只引用，不在无新证据时重新生成。

公开 API 类型从统一契约生成前端客户端、JSON Schema 和示例骨架；格式化、迁移脚手架、静态检查和报告统计由工具执行，之后检查产物。不能把代码生成工具输出视作未经验证即可发布的代码。

所有原任务书必需文档保留。共享内容只维护一次，其他文档链接到准确章节；API 细节以实际 OpenAPI 为准，文档不能只剩标题和相互循环链接。

### 3.3 代理与推理分配

默认一个主执行者。仅当任务输入输出独立、文件不冲突且预计能减少总返工时，最多再增加两个子代理；禁止递归代理树，禁止每个小函数都启动独立开发与独立评审代理。

子代理只接收相关契约、目标文件、验收用例和必要约束，返回差异、测试证据和问题，不重述全项目。并行写入共享契约、锁文件、迁移、鉴权或工作流状态机必须由一个所有者协调。

如客户端允许调整模型与推理强度，架构、科学计算、并发和安全审查优先使用足够能力；格式、类型生成及明确的局部修改使用常规配置。不得假设能从任务提示词控制客户端不支持的模型参数，也不以全程最低推理模式换取表面节约。

进度更新短且有实质：完成了什么、验证证据、当前阻塞。不要反复宣布将做什么，不逐行粘贴代码和测试日志。最终交付用验收摘要和文件位置，不再把整份任务书重新输出。

## 4. 降低工程复杂度，但不减少能力

新工程优先维持一套 TypeScript 前端、一套 Python API、一套计算 worker。API、worker 共享有版本的核心包；不把每个能力各建微服务。保留 PostgreSQL/PostGIS、选定的一种队列实现和对象存储，不并行维护两套 ORM、队列、鉴权或图数据真源。

原有 Model/Scene/Workflow/Binding/Manifest 契约先完成并测试。业务算法不放路由处理器或 React 组件中；核心计算尽量是显式输入输出的纯函数，I/O 和运行环境放 Adapter。依赖方向为应用与领域包依赖通用核心，核心不依赖海岸带专用名称或 GeoAI。

模型参数表单可由契约生成，地图编辑、结果比较和领域审核保留必要的专业交互；不能为追求生成化把所有页面做成原始 JSON 编辑器。

优先复用成熟库，但只引入当前必需依赖，记录依赖版本与许可证。锁定 Python/Node 依赖和部署镜像，不用漂移的 latest 作为验收环境。实施时核对实际版本文档，避免凭记忆调用过时 API。

## 5. 系统运行时的 LLM 成本控制

本节是 CoastMAS 自身的模型调用策略，与 Codex 编程所消耗的 token 分开统计。

### 5.1 默认调用路径

| 操作 | 默认 LLM 调用策略 |
|---|---|
| 运行已保存且预检通过的工作流 | 0 次；普通任务引擎执行 |
| 单位、CRS、垂向基准、数据覆盖、参数范围和权限校验 | 0 次；确定性代码执行 |
| 已声明模板内的明确目标及参数提取 | 优先规则；不得把无法理解的内容悄悄丢弃 |
| 模板外自然语言任务规划 | 检索候选后 1 次结构化调用，必要时最多再 1 次修复或重试 |
| 已有结果的地图、表格和固定报告 | 0 次；可选自然语言解释单独授权并计入用量 |

默认 `max_provider_requests_per_plan=2`，包括自动修复、HTTP 重试和 SDK 内建重试实际发出的请求。预算由一个全局规划 trace 管理，不能在 parse/recommend/build-workflow 三个端点分别重置。关闭或显式计入隐藏重试；并发请求通过原子预算扣减控制。

解析、推荐和构图可共享一次经过校验的规划产物，不要求每个 API 都独立调用 LLM。不得将图的每个节点交给一个聊天代理运行。

### 5.2 按需候选与紧凑结构

默认先检索最多 6 个候选模型的简短契约和必要邻接关系，可在同一预算内扩展到 12 个；候选不足或需求复杂时明确报告缺口，不能因截断候选而给出无依据“最佳模型”。这是可配置初始值，不是科学常数。

提示中只包含任务所需的能力、变量、约束、证据标识与场景摘要，不塞入全部文献、所有模型说明书、历史聊天、整张影像或完整数据库。优先使用安全的数据摘要；未经授权不得把委托方数据发往外部 LLM。

使用明确 JSON Schema/结构化输出；字段名保持可读。模型返回只接受已注册的能力与模型 ID，不执行自由文本代码。截断或不合 schema 的输出必须标记无效，不能拼一个看似完整的结果继续运行。

输入长度、最大输出、总调用数、超时和项目预算可配置。默认值以被选提供方实际能力校验；达限就安全拒绝继续生成或使用已经验证的确定性路径，不静默删除约束。系统启动和三个确定性演示不得依赖外部 API Key。

### 5.3 两种缓存分开设计

应用级缓存：使用规范化且不可变的场景版本、模型/工作流版本、数据内容校验和、变量映射、全部参数、约束、算法环境、随机种子及访问范围生成缓存键。命中时再次检查当前权限、数据可用性和模型启用状态；有变化则失效。按用户目标近似相似的“语义命中”只能作为候选，不能替代科学运行依据。

提示前缀缓存：只有提供方和选定模型实际支持时才启用，并根据实施时官方文档配置和验证命中。不能把固定前缀当作必然命中，也不能把缓存 token 当作不占上下文或完全免费。没有提供方缓存也必须保持功能正确。

缓存复用同样创建新的运行记录，标记 `reused_from`、权限检查和版本，保留原始证据，不伪造为重新计算。可禁用缓存做复现和性能对照。

### 5.4 成本可观测性

每次调用记录 trace、model、provider、prompt/契约版本、input/output tokens、cache read/write tokens、可用时的 reasoning tokens、请求数、延迟、状态和来源。保留提供方原始 usage 映射，注意子项包含关系，不把 reasoning 或 cached tokens 再重复加到总量。

未返回的字段记录 null/UNAVAILABLE，不按字符数冒充真实用量。费用只有在配置了有来源、币种和生效时间的费率后才估算；无费率则不编造金额。开发期间 Codex 总用量仅在客户端确实提供时记录，CoastMAS 应用无法自动获知的部分如实标记不可取得。

## 6. 强类型、边界与可维护性门禁

Python 公共接口、核心领域模型、Adapter 输入输出必须有类型声明；核心域启用严格类型检查。前端启用 TypeScript strict。动态外部数据用 unknown/显式 schema 解析，不允许把大量 Any/any 扩散到业务内部。

统一错误结构：稳定 error_code、可理解 message、必要 details、request_id。服务端权限是唯一执行依据；前端按钮禁用不是鉴权。异常必须保留原因，不允许吞错后返回默认“成功”。

数据库落实外键、唯一约束、不可变版本和合理事务。并发修改采用版本号或等效冲突检测；Job 状态流转使用条件更新，不能只靠前端顺序。结果通过 ResultRevision/Manifest 引用旧版本，不覆盖已有产物。

函数与文件按单一职责拆分；不设置机械行数上限诱导碎片化，也不为了少 token 把不同模块塞入一个巨型文件。注释解释科学假设、坐标与单位、非显然边界，不重复代码字面含义。

禁止广泛关闭 lint/typecheck、滥用忽略注释和整库降低标准。第三方缺少类型或确需兼容的局部例外必须写原因、范围和测试；例外不能覆盖整个项目。

## 7. 并发、缓存与执行质量

提交任务使用项目与用户权限范围内的幂等键及参数指纹；相同键但参数不同应冲突，不得复用另一任务。重复队列投递、worker 重启和短暂连接故障不得导致重复发布、重复扣费或覆盖结果。

长任务异步执行，CPU/GIS 运算不能阻塞 API 事件循环。取消必须传递到可取消 Adapter/子进程；不支持立即中止的模型应如实显示取消请求/等待结束状态，不能立即假报取消。已取消任务不能被迟到结果改成成功并发布。

每个 Adapter 明确超时、资源上限、退出码、产物校验和清理行为。重试只针对可重试错误且有上限；科学约束错误不靠重试修复。远程调用的不确定状态要记录并进行幂等查询，不盲目再提交昂贵计算。

采用中间文件暂存、完整性检查、原子发布及数据库事务协调。对“文件写入成功但状态落库失败”等情况建立恢复与清理机制，不能出现成功记录指向半成品。

## 8. 科研算法质量要求

以下是补充测试和边界要求，不增加未经授权的科学能力声明。

| 核心领域 | 必须验证的行为 |
|---|---|
| 单位与语义 | 可转换的同维单位转换后结果一致；不同物理量、统计时间含义和语义不能仅靠字段名相近直接连接。 |
| 地理基准 | 缺 CRS、不可用坐标转换、垂向基准缺失或不匹配按规则阻断；有效可转换的 CRS 差异应适配，而不是一律报错。 |
| 栅格映射 | 类别量与连续量使用适当方法；总量重分配检查覆盖与总量守恒；NoData 不自动变成零或低风险。 |
| 海平面筛查 | 明确基准水位与增量的关系，不能把 +0.5m 当作无基准绝对水位；记录海侧种子、4/8 邻接、NoData 与屏障处理。仅为连通性筛查，不称水动力求解。 |
| 分区统计 | 单位、面积算法、交叠区域、无覆盖区域和分母明确。行政单元人口按淹没面积分摊必须声明均匀分布假设，不能称为实际精确受影响人口。 |
| 权重与 TOPSIS | 常数列、全零、缺失值、负向指标、非法或零总权重、理想解距离退化不产生 NaN/Inf 或伪分级。边界策略写入契约。 |
| 多期评价 | 采用固定或明确版本化的归一化参考与权重；独立按每期重新缩放的相对得分不能直接宣称为绝对改善趋势。 |
| ML 示例 | 固定种子、训练/验证分离、预处理一致；空间/时间数据划分避免可识别泄漏。Feature importance 不是因果归因证据。 |
| 空间优化 | 验证求解状态、硬约束、不可行与超时；未证最优时标明 incumbent/近似解，不把未收敛结果报告为最优。 |

优先使用可手算的微型案例、独立参考实现、性质测试和固定输入金标准校验，不以“函数返回了一个数组”证明计算正确。科学容差按算法和尺度写清，不用一个随意的大容差让所有测试通过。

## 9. 安全底线

所有敏感配置使用本地环境或授权秘密管理机制；`.env`、访问令牌、实际数据库内容和敏感日志不提交。演示账号不得变成公开生产弱口令；绑定本地地址作为默认部署边界。

上传限制类型、大小、解压路径与资源消耗；外部 URL/HTTP Adapter 限制协议、目标与重定向，防止 SSRF。访问内网专业模型必须是管理员显式允许的服务，不能接受任意用户地址。

CLI 只允许已注册模板、参数数组、工作目录与超时，不用未验证字符串拼接 shell。DockerAdapter 使用受限 runner，不能为图省事把宿主 Docker socket 暴露给 Web/API 和任意用户任务；不默认 privileged，不随意挂载主机目录。

Python/ML 模型插件只接收可信、授权维护者提供的代码与产物；不能安全反序列化的模型格式不得允许任意用户上传后执行。模型/数据说明中的文字视为不可信内容，不能成为覆盖系统约束的指令。

数据库降级、删除数据卷、对外公开、付费服务创建及超出授权范围的实测不能用“一次完成”绕过许可。可在独立本地测试环境完成的工作继续进行，阻塞项单独记录。

## 10. 自动化验证：日常增量，交付全量

研发中每次改动跑受影响单元、契约与相关集成测试，不为格式改动重复重建整个环境。核心契约、依赖、权限和调度变更必须扩大回归范围。最终验收必须在最终交付代码上完整运行；若修复后证据已经过期，重跑受影响门禁及最终验收集合。

至少提供以下真实可执行入口，命令名称可以遵循已有项目规范，但含义必须一致：

| 入口 | 必须实际执行 |
|---|---|
| `make check` | Python lint/format、严格核心类型检查、前端 lint/typecheck、生成契约漂移检查 |
| `make test` | 单元、性质、契约、数据库/存储/队列/Adapter 集成测试与覆盖率统计 |
| `make e2e` | 真实 API/worker/数据库支持的关键用户路径；不能全程拦截 API 返回 Mock 成功 |
| `make research` | 确定性算法基准、错误注入、三场景复现及规划对照；真实 LLM 实验独立标识 |
| `make benchmark` | API/地图/任务耗时、冷热缓存、失败率及可获得的 LLM 用量测量 |
| `make acceptance` | 整合检查、构建、临时库迁移、部署健康、E2E、演示、科研与证据汇总，必选失败返回非零 |

命令不能只有 echo、空函数或始终 exit 0。容器生命周期和资源名称限定本项目，绝不 down/delete 无关项目。

以下覆盖率是本项目新增建议门槛，Codex 应实现，不能宣称是通用行业标准：Python 业务代码行覆盖率 ≥85%、分支覆盖率 ≥80%；约束/绑定/工作流状态机核心包行覆盖率 ≥90%、分支覆盖率 ≥85%。排除自动生成代码可以，但列出理由；不得排除困难业务代码来刷指标。前端除类型检查外，必须覆盖关键组件行为和所有必选操作的 E2E。覆盖率达标不替代正确性与安全审查。

最终必须有一次面向差异和真实数据流的集中审查，重点是越权、数据混用、状态竞态、科学边界与异常分支。若有合适审查代理可做一次独立审查；没有则做明确的主执行者复查，不伪称独立审查。记录问题、修复和验证，不为刷审查次数启动代理循环。

## 11. 必选验收用例与证据

除原任务书测试外，至少加入：

1. 保存的工作流重新运行时 LLM 调用数为 0；普通规划符合请求预算，非法 JSON 修复和网络重试不会越过上限。
2. 未配置外部 LLM 凭证时三个演示完整运行，界面显示确定性模式；真实 LLM 对照不混入这些结果。
3. 数据、参数、基准、模型版本或约束改变导致缓存失效；撤销权限后即使有缓存也拒绝读取。
4. 重复提交、队列重复投递、worker 重启、取消与完成竞态不重复发布、不覆盖旧结果、不产生错误成功状态。
5. 同一不可变输入在固定环境和种子下重复运行，结果满足预先声明容差，RunManifest 和输出校验可追溯。
6. 创建场景—规划—绑定—预检—执行—地图/表格—成果溯源的真实 E2E；失败场景能定位缺失数据或冲突条件。
7. 核心算法的常数列、零值、NoData、无交集、退化 TOPSIS 与优化不可行测试。
8. GeoAI 可选集成契约可由独立测试客户端调用，移除 GeoAI 后 CoastMAS 仍可完整运行。
9. 日志及错误消息不泄露密钥、连接字符串和未经授权数据；核心端点服务端越权测试通过。

证据包含命令、开始/结束时间、退出码、commit/工作树标识、环境版本和产物路径。状态用 PASS/FAIL/BLOCKED/NOT_RUN/NOT_APPLICABLE；最后一种必须有符合范围的理由。必选项 BLOCKED、FAIL、NOT_RUN 不计入通过率，不得移除分母使通过率虚高。

`artifacts/acceptance.json` 保存机器可读结果；`docs/acceptance-report.md` 保留人工可读概要、全部未完成项及限制。最终报告必须区分：功能开发、部署验证、科学示范验证、真实外部实验验证，不合并成一个绿色“完成”。

## 12. 节省效果的报告方式

分别报告开发过程可取得的用量和 CoastMAS 运行时实测用量。没有可比较基线不得给出节省百分比；没有客户端 token 统计不得用文件字数、工具次数替代真实计费。

对运行时选择相同任务、同一模型与环境，对比规划调用数、输入/输出与缓存 token、延迟、失败率、硬约束识别率、工作流有效率及人工修订量；缓存命中和冷启动分开。确定性结果用数值与空间一致性验证，LLM 结果用已冻结的任务集与判据评估。

优化不得增加高严重度科学或权限错误，不得省略工作流必需节点。若 token 降低但正确性下降，报告退化，恢复可验证的配置或明确禁用该优化。不要为追求节约数字删掉难样本、隐瞒失败请求或提高通过阈值。

最终交付重点：可运行的软件、真实验收证据、可维护代码和可复现结果；简短汇报是表达方式，不是减少实施工作的借口。
