# 时间适配

从主菜单进入“时间适配”，选择沿用研究区的场景，填写数据名称、来源、许可证、物理变量与输入/输出单位，再选择统计含义、方法和缺测策略。按实际时间录入观测，缺测值留空；时刻和区间端点必须带时区。

点击“保存时间适配工作流”后，系统冻结输入文件、生成独立场景与单节点工作流，并跳转到已选择该场景的运行页面。执行“科学预检”→“提交运行”，在运行中心打开“查看不可变结果”。结果页展示数值、单位、方法、观测数及源/目标时间；可下载完整版本与溯源。原场景不变，数据目录和工作流目录保留新记录。

已有结构化文件也可经“数据目录”上传：顶层使用 `request` 键，其值为 `TemporalRequest`；需匹配专用模型输入契约。新页面提供逐项表单，无需编写 JSON。准备接口使用权限检查和幂等键，同键不同输入返回冲突。已禁用或已归档的模型不能被准备流程重新启用。

时间适配是确定性的可信计算节点，不调用 LLM。输入以 UTC 可比较的带时区时间记录每条观测的实际支撑；元数据不能用猜测的固定频率替代不规则观测。

| 方法 | 适用含义 | 运算约束 |
|---|---|---|
| nearest（最近观测） | 连续、瞬时、类别的点观测 | 目标在观测范围内；等距选择较早观测；不跳过缺测值 |
| interpolation（线性插值） | 连续、瞬时的点观测 | 仅相邻两点内插；不外推；任一相邻值缺测则传播缺测 |
| mean（时长加权平均） | 连续量的区间平均 | 区间必须无重叠、无空档地完整覆盖目标窗口；按实际 UTC 秒数加权 |
| sum（累计） | 总量的区间累计 | 同样要求完整区间分割；每条累计值只加一次；不能使用含偏移的单位换算 |
| min / max（观测最小 / 最大值） | 连续量、瞬时量 | 返回所选观测支撑值的极值，不代表未观测期间的连续极值 |

不允许将降水累计量求温度式平均，也不允许给类别值作插值。区间不能被静默截断；需要部分区间时必须提供适用科学模型，不能假设区间内均匀。所有输入值与输出值必须有限，缺测显式为 `null`，策略为传播或拒绝，不能自动填零。

输入采用 `TemporalRequest`（自动生成的契约中提供字段），包含物理变量、输入和输出单位、统计含义、点/区间支撑、实际观测、方法以及目标时刻或窗口。外层工作流 JSON 变量是结构容器，因此单位为 `1`；内部物理单位由强类型契约和 Pint 校验，并原样记录到结果。数据目录 `time_resolution=explicit_support` 仅对该专用契约开放，不能用于绕过普通模型的时间尺度约束。

上传/读取会检查文件观测首尾与目录时间覆盖完全一致，校验方法、单位、空档及缺测策略，并把这些声明记录到冻结数据资产。科学预检与执行都会要求目标区间与场景时间范围完全一致。结果包含方法、目标与实际使用的源区间、观测数、有效观测数、单位及解释；输入文件、工作流、场景和模型都通过现有不可变版本与校验和追溯。

可手算基准：10 ℃ 持续 1 小时与 20 ℃ 持续 3 小时，时长加权平均为 17.5 ℃（290.65 K）；10 mm 与 20 mm 的区间降水累计为 0.03 m。基准属于自动化验证，不作为用户界面中的真实影像演示数据。

当前验证进度以 `docs/STATE.md` 和 `artifacts/evidence/` 为准；不将尚未完成的界面或最终验收标为通过。
