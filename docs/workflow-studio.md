# Workflow Studio

入口为工作流目录的“新建工作流”，或已有工作流的“编辑工作流 / 另存副本”。编辑器加载本项目目录和引用的精确模型版本；不会将旧节点静默升级到最新模型。

## 使用

1. 从工具箱拖入模型，或点击添加。节点显示模型名、版本和真实输入输出端口。
2. 从输出端口拖到另一节点的输入端口。循环依赖和同一输入的多个来源会立即拒绝。连接列表提供可访问的删除按钮；删除节点同时删除关联连线、输入绑定、参数绑定和输出声明。
3. 选择节点填写参数。只有模型声明的非空默认值才会自动填写，必填参数不会猜值；0 是有效的显式数值。参数编辑移除同一参数的旧独立绑定，避免双来源。
4. 为未连接上游的输入选择数据版本，并勾选需发布的输出。绑定初始状态为 MANUAL_REVIEW，选择数据不等于科学校验通过。
5. 选择真实场景，点击“校验当前草稿”。服务端加载授权资源、检查科学契约和可信运行注册，返回错误节点；不保存资源、不提交任务。任何草稿或场景变化都会使旧响应失效，包括较晚到达的响应。
6. 保存创建 v1，修订通过 expected_version 生成下一不可变版本，冲突不会覆盖他人的修改。另存副本创建独立标识和 v1，保留全部语义约束及固定依赖版本。
7. 保存后在详情中选择场景、科学预检并提交运行。服务端再次检查版本、权限、资源启停和运行资格；只有真实 worker 成功发布后才出现结果链接。

结构合法但科学不完整的草稿可以保存，不能因此绕过运行关卡。草稿预检接口为 `POST /api/v1/workflow-drafts/validate`，契约见 [OpenAPI](openapi.json)。节点位置是编辑会话视图状态，不进入科学 DAG 或结果计算身份。目录目前一次读取最多 500 条；达到上限明确提示，未加载项不参与编辑。

## 实现与验证

- 纯状态变换：`apps/web/src/workflow-editor.ts`；可复现循环、多来源、默认值、删除依赖和参数冲突测试。
- 真实端口交互、保存、复制、修订、历史版本及 worker 结果：`apps/web/e2e/workflow-editor.spec.ts`。
- 草稿不持久化、权限和运行资格：`tests/integration/test_workflow_drafts.py`。
- 编辑器受控画布保存节点测量/位置和连接选择；视野更新为异步操作，端口拖动验证必须等待真实布局并检查命中，不能用预估坐标或直接调用状态函数代替鼠标操作。实现参考 [React Flow 受控交互](https://reactflow.dev/learn/concepts/adding-interactivity) 和 [节点测量](https://reactflow.dev/api-reference/hooks/use-nodes-initialized)。

具体证据在 `artifacts/evidence/*workflow-editor*`。早期浏览器失败包括标签定位、端口名误读，以及拖入节点与后续节点重叠，记录全部保留。全范围验收仍以需求追踪表和最终门禁为准。
