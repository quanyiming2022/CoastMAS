# 评价中心

指标体系为项目内不可变版本资源：IndicatorFrameworkSpec。每个指标保存稳定标识、名称、分类、单位、正负方向、公式输入列映射、公式、固定归一化上下界、权重方法和权重。用户须填写科学边界和单位；编辑器空值不能作为有效契约保存。五个内置分类只是 DEMO FRAMEWORK 示例，不代表唯一评价理论。

公式使用已有受限 AST 数组解释器，支持多列算术、比较、where、sqrt、log、abs；不执行 Python 源码。输入按明确单位转换到基础单位；加减和比较常量采用相邻量的基础单位，归一化边界采用输出单位。单位不兼容、未知列、危险表达式、除零、非有限数和参考范围越界均拒绝。归一化边界不随时期重新估计。所有时期共享同一种权重方法，熵权在全部时期联合估计。手工零权重允许，但总和必须大于零。

浏览器路径 `/assessments` 提供体系列表、新建、指标增删、公式列绑定、阈值编辑、修订、只读历史、依赖保护归档和数据准备。观测来自项目中已验证的 JSON indicator_frame 文件，实体和时期必须对齐。服务端按输入列名绑定，保留真实零值。当前准备上限为 16 MiB 输入文件和一百万观测/派生数值，最多一百个指标。

准备操作锁定输入和体系资源，验证权限与版本，读取并校验真实 S3 字节，实际计算公式并重新检查结果，再保存独立数据资产。新文件包含体系、观测版本和权重方法；数据库外键依赖固定两个来源。相同幂等键不重复产生文件，不同输入版本不能复用同一键。元数据中的来源文字不替代外键证据。

“生成评价方案”使用服务端读取的体系权重方法和准备文件；多个时期自动加入 change 节点。方案复用确定性规划器与共同科学预检，不调用外部模型。多期 TOPSIS 在没有共同理想点定义时拒绝。用户查看方案后保存工作流，再通过现有运行界面执行预检、队列提交、独立 worker 和不可变结果发布。

空间支撑可明确声明管理单元、行政单元、自定义多边形或网格；准备阶段严格匹配观测支撑。四类支撑分别注册独立模型签名，严格按实际输入匹配，不把网格或行政单元伪装成管理单元。新增15个签名后共23模型，旧签名保持原样。四类实际S3输入、DAG执行和多期金标准均通过（023851387059Z）；混合目录歧义须明确选择观测（024605717476Z）。
