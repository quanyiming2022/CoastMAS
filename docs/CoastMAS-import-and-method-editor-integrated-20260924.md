## 0. 本轮真正要解决什么

用户希望：一次打开有效的导入界面；系统知道本次工作需要什么资料；按实际文件和已选方法自动识别相关内容；只对真正缺失或歧义的部分提出具体修复；导入后直接查看并在适用入口加入当前研究。

当前截图能确认：出现了只含“添加资料”的“上传文件”中转弹窗；后面才出现真正文件选择；孤立TFW进入了长补选卡片；93字节进度被显示成0.00 MiB；背景已有一份名称对应的TIFF。截图不能证明组件是否嵌套、TFW是否真的写成独立任务输入、或已有TIFF是否与新附件属于同一原始数据包，必须定向查实际请求、记录和关联证据。

**目标流程：入口意图 → 本次资料要求 → 一次选择 → 安全读取与自动组包 → 只处理必要问题 → 受管资料 → 按原入口绑定/展示。**

“自动找到同一数据包附件”和“根据研究推导其他业务输入”是两件事，不能只按文件名互相推断。

## 1. 固定入口：一次操作打开真正能选资料的界面

### 1.1 入口契约

| 入口 | 单次点击后的首个应用界面 | 已完成导入后的效果 |
|---|---|---|
| 数据资源“导入资料” | 统一导入对话框，本机文件区立即可用 | 登记当前项目资料，自动预览；不自动改变研究输入 |
| 研究输入“添加资料” | 同一个对话框，可直接选择本机文件或已导入资料 | 按本次明确添加意图加入该研究；只对可确认角色做自动映射 |
| 某指标/步骤的“补充资料” | 同一个对话框，显示该角色的具体要求和候选 | 填充这一角色；歧义时仅要求选择对应变量/资料一次 |
| 已存在资料的“补充附件” | 同一个对话框，固定该主资料及版本 | 只补该资料附件；影响解释时新建资料解释版本，不新建一个无关指标 |
| 方法/模型“导入” | 对应方法/模型导入器 | 进入方法或模型目录，不能误走科研数据导入服务 |

删除只含“添加资料”按钮的中转弹窗及同义中转页面。整个操作同时至多有一个应用模态框；原生操作系统文件选择器不算额外应用模态。

本轮“一次打开”指点击一次业务入口便看到有效选择界面，不承诺绕过操作系统文件授权。页面应直接提供“选择文件”与“选择文件夹”操作，拖放也是等价入口，不再先问“是否要上传”。

文件选择成功后自动接收并检查明确选中的文件；资料能确定完成时自动登记，无需额外点“继续成组接入”。有歧义、范围过大、身份/解释冲突时才进行必要决策。对已有资料选择，提供一次“加入研究”提交选择是有意义的操作，不再套确认弹窗。

### 1.2 不根据地址栏猜测导入目标

即使当前地址为 `/methods`，用户点击的是研究“输入”中的添加按钮，目标也应是该研究输入，而不是方法库。通过入口传入的固定上下文判断，不读取“最近一次选中的对象”代替。

## 2. 根据任务需求提示资料，而不是按任务名称硬编码文件扩展名

### 2.1 需求来源

由下列已知信息共同计算：研究目标、已选方案版本、已选指标配方/空间化方法/模型接口、当前要完成的动作、明确的分析范围和时期、已绑定且实际有效的资料与产物。

只采用真实发布的版本和受支持的输入契约；方法缺输入声明属于开发/方法维护问题，不能让普通用户填内部schema。

任务目标尚未细化时允许先整理资料和预览：显示资料类型建议，不提前生成“缺少全套年鉴/边界/影像”的错误。

### 2.2 需求必须表达替代路线

例如“植被指标”可能由已确认的成品指标提供，也可能从有合适波段的影像生成。系统表达为“成品指标 OR 合适影像与配方”，不能同时强要两套资料。

需求项包括：业务角色、数量要求、必须/可选/条件必需、候选来源、允许资料表达、所需字段/波段/单位/时期/空间条件、所属步骤、可接受的转换路径、尚待决定的分支。

内部可以采用all_of/any_of条件结构，但界面只显示“任选其一”“已有资料可生成”“需补充”等业务信息。

### 2.3 示例需求矩阵（是产品设计，不是所有任务固定要求）

| 当前选择 | 要求与可接受资料 | 不应强制要求 |
|---|---|---|
| 仅导入查看/质量检查 | 安全且可读取的资料；上图时另需可靠定位 | 评价方法、评分方向、权重、行政边界 |
| 综合评价：采用已有指标 | 能表达所需指标的栅格、矢量数值列或有可信对象键的表格 | 每次都再传原始影像、土地利用、年鉴 |
| 从影像生产NDVI | 可提供实际红光与近红外的产品，适用质量规则由配方决定 | 不按任意RGB三通道假定具备NIR；不在已有可信NDVI被选用时又强要原影像 |
| 土地利用距离/比例 | 相容的地类栅格或几何图层、明确分类字段/字典；也可引用已确认同定义的指标 | 不能仅因都叫distance而替换指标对象 |
| 年鉴行政关联 | 统计表（或可提取文档）、相应行政边界/代码映射 | 不必有灯光、POI和回归模型 |
| 年鉴回归空间化 | 统计表、完整控制区、适用辅助特征与实际训练方案 | 不将所有候选辅助数据都设为必填；不把同一行政值复制到像元制造样本 |
| AHP权重 | 指标层次/身份与已存判断或CSV/XLSX判断矩阵 | 为填写判断而强求先上传全部影像 |
| 两期变化 | 两期可比数据及实际方法要求的时间/类别/配准条件 | 不按文件修改时间自动确定两期 |
| 回归训练 | 明确特征、真实响应/样本关联、实际划分要求 | 不假造响应值 |
| 已训练模型预测 | 固定模型签名所需的新特征与映射 | 不强求预测对象真值才能做预测；验证另行处理 |
| 空间聚类 | 实际方法所需特征与可执行规则 | 不要求响应变量或“越大越好”方向 |
| 空间优化 | 候选单元及所选方案实际需要的目标/成本/约束字段 | 不固定要求每种风险/成本列，缺必需成本也不能填0 |

文件格式过滤来自输入契约与当前后端实际解析能力的交集，保留“查看其他可导入格式/仅导入资料库”。CSV、GPKG等可能承担不同角色，不能只按后缀判断科学适用。

### 2.4 用户看到的需求状态

- 已使用：已绑定并核对本角色，标出真实资料/变量。
- 可复用：项目库有候选，但还未加入本次任务。
- 可从现有资料生成：配方及依赖确实存在，尚未执行；不能显示成“已生成”。
- 待选择：存在多个合适候选或替代路线。
- 需补充：所选路径必需输入确实缺失。
- 待核对：缺必要单位、含义、时期或空间依据。
- 可选：缺失不阻挡当前选定操作。

识别出的候选不得通过算法相似度直接变为“已认可科学定义”。文件名只提供线索；有明确入口、固定可信元数据或已经确认的映射才可自动绑定语义。

## 3. 一个紧凑对话框承载全部导入状态

建议桌面宽约800px，高度随内容且不超过工作区约80%；正文14px，工具栏32—36px，列表行36—40px。这些是本项目尺寸起点，不是强制行业标准。

### 3.1 布局

1. 标题行：`添加研究资料` / `导入项目资料` / `补充定位附件`，标题由入口决定，右侧关闭。
2. 上下文摘要：项目和目标研究/指标简短显示，不重复创建名称，不显示整串ID。
3. 相关需要：最多显示当前角色或当前阶段最重要的缺项摘要，可展开其余；不是铺一张全八步检查报告。
4. 来源标签：`本机文件｜已有资料｜已授权来源`。没有可用且有权来源时不强迫配置它。
5. 选择区：一个主要的“选择文件”，旁边“选择文件夹”或拖放；不摆两套“未选择任何文件”大框。
6. 逻辑资料表：`资料｜识别结果/用途｜状态｜操作`。关联附件默认折叠，技术详情可查。
7. 单一结果摘要及“完成/返回研究”；正常自动导入没有二次“同意导入/继续成组”关卡。

“支持什么”用一行随当前角色更新的短提示，详细格式放“支持格式”。错误显示在对应资料行；不能每附件都复制一张重选表单和同一大红框。

### 3.2 常见状态

无文件：显示真实的选择入口和一条简短提示。
已选完整资料：自动安全接收、组包、登记、预览；不再额外确认已明确意图。
部分资料缺必要内容：成功项继续；问题行给一个最相关修复。
全部成功：短摘要如“已导入2份资料，已加入本研究”；数字来自实际登记与绑定回执。
资料入库成功但绑定失败：明确两阶段结果，给“选择研究/重试加入”，不能让用户重新传几百MB。
上传关闭：关闭UI不伪装后台继续读取本机文件；服务器已接收完整对象可后台处理，仍需本机字节时明确未完成并支持重选续传。

## 4. 关联文件分两种，不混为一个“自动识别”

### 4.1 技术附件：组成同一逻辑数据集

| 文件 | 角色 | 规则 |
|---|---|---|
| .tif/.tiff | 主栅格 | 有独立可读像元及资料身份 |
| .tfw/.tifw/.tiffw/.wld | 世界文件 | 提供仿射定位，不独立提供完整CRS；不是CSV或指标 |
| .tif.aux.xml 等已识别PAM | 辅助元数据 | 按实际内容保留定位、掩膜/缺测或其他解释；不是所有XML都属于PAM |
| .ovr | 概览 | 用于适用显示优化；不作为评价主栅格 |
| .msk及已识别掩膜附件 | 有效性信息 | 检查尺寸/对应关系，不能遗漏导致无效值进入分析 |
| .shp/.shx/.dbf及.prj/.cpg等 | Shapefile资料的组成文件 | 按所选处理用途和驱动能力检查必要成员；不逐附件独立建指标 |
| 产品清单、STAC/CSVW/其他明确标准元数据 | 产品/字段/资产关系 | 仅在受支持档案及授权范围内解析引用 |

主栅格内嵌定位已充分时，不因没有TFW/AUX/OVR一律报缺件。缺概览不阻挡原数据使用；损坏概览可以明确舍弃并从主件生成受管显示缓存。辅助文件携带唯一关键定位/掩膜时不能简单当可选缓存忽略。

### 4.2 业务关联：不同资料共同支持本次研究

年鉴与行政边界、两期影像、土地利用与分类字典、人口与辅助数据是不同资料对象。关系从任务/配方/方法和已确认语义取得，不因文件同目录、同名前缀就自动当成一组必需资料。

相同波段尺寸、相同单位不代表指标含义相同；有边界的某年数据不自动适用于所有年份。统一到同一目录或同一网格也不等于科学适用。

## 5. 自动组包和已有主件关联算法

### 5.1 查找范围

允许的范围依次为：用户本次实际选中的文件；用户明确选择的目录/ZIP范围；同一未完成导入会话；当前项目内用户有权访问的受管资料及其成员清单；用户明确指定的已授权来源位置。

单选一个本机TIFF，不代表网页取得其父目录权限。没有授权时只能提示补选附件或选择资料夹，不能声称已扫描完整目录。不能把浏览器假路径变成服务器绝对路径。[R3–R5]

目录授权不等于把目录及所有后代全部上传。优先识别主件与关联附件；对于多个逻辑资料/较大范围，先显示清单和总量，用户明确选择导入范围。不得静默遍历盘符、符号链接或无关子目录。

### 5.2 匹配步骤

1. 读取低成本签名、容器头、明确产品标识、相对路径和文件名，先分主件/附件/普通表格/文档/未知。
2. 按同一授权范围和目录关联语境生成候选；扩展名/名字只生成候选，不能独自证明内容身份。
3. 对候选核对可用证据：已有成员关系/受信manifest/导入会话、主件固定版本、波段与尺寸、定位、来源与时期、相应附件实际格式。
4. 同一已确定数据包内关系唯一且相容时自动组包。存在多个主件或解释冲突时只提出该项选择/差异。
5. 受管存储即使以hash命名，也要在隔离读取空间重建驱动所需的安全文件名与相对关系。
6. 返回一个逻辑资料和可展开成员清单。任务输入按逻辑资料/用户选定的变量引用计数，不按附件数计数。

### 5.3 截图中的孤立TFW怎样处理

收到 `PRD_distance_agricutual land.tfw` 后先识别其角色和6参数结构。截图背景可见名称对应TIFF，因此应检查当前可读资料库/研究引用是否已有对应主件，而不是无条件重传主影像。

- 已有明确的数据包关联：校验实际内容后自动纳入该数据包处理。
- 库中只有同名候选、没有足够身份依据：提示“发现可能对应的已导入影像”，提供一次“关联这份影像/选择其他影像”；不凭名字覆盖定位。
- 没有可用主件：显示“这是定位文件，请选择对应影像”，提供“补选影像”。已安全暂存TFW保留；补件后自动重新匹配，不需要用户再点“继续成组接入”。
- TFW存在但源CRS仍未知：允许安全登记主资料及非地理预览，仅阻挡需要定位的动作，具体提示CRS缺失。
- 源文件与TFW冲突：对比原/候选定位；需依据选择，不能直接依赖驱动隐含优先级消除告警。

TFW不应独立算1份已用评价指标；“93/93字节”应显示93 B，不显示0.00/0.00 MiB。

### 5.4 已有版本与后补附件

补入会改变定位、mask、单位或其他科学解释的附件，要生成新的解释/资料版本，并仅使真正依赖它的下游待更新。原TIFF和历史结果不改写。

纯显示概览重建只改变显示缓存/解释记录相应部分，不无故使权重和科研结果失效。附件若虽称概览但被发现含实际不同数据，按冲突处理，不私自替代主资料。

不要为了减少输入项将历史错误记录物理删除。按权限提供重分类/关联与当前输入修正，并保留审计。

## 6. 缺项分层：只阻断确实受影响的动作

| 问题 | 接收/受管 | 原值查看 | 地理显示 | 对应计算 |
|---|---|---|---|---|
| 安全检查失败/越权 | 拒绝或隔离，不承诺受管可用 | 不开放危险内容 | 不开放 | 不开放 |
| 孤立附件无主件 | 可安全暂存为待关联，不建独立评价输入 | 可查看附件信息 | 无主影像不能画出真实栅格 | 不能替主数据 |
| 主数据完整，缺可选概览 | 正常 | 正常 | 按预算生成预览 | 不因此阻挡 |
| 主数据可读，缺可靠CRS | 可登记待定位状态 | 可看非地理图像/表格 | 待补/修正定位 | 阻挡依赖地理定位的计算 |
| 科学单位/概念未知 | 可登记 | 原值查看 | 有定位则上图 | 仅阻挡需要这些定义的算子 |
| 任务需要的另一个资料缺失 | 已收到的资料正常保留 | 正常 | 满足条件的正常 | 只阻挡对应未满足节点及后代 |
| 输出网格不同但有合法转换方案 | 可登记 | 正常 | 显示投影可用 | 显示“需对齐”，不是“文件错误” |
| 科研方法未选/缺权重 | 不影响导入 | 正常 | 满足定位即显示 | 对应评分/赋权/综合节点待配置 |

无独立业务验证不等于主文件损坏。不能把所有问题统一称“导入失败”或“未通过科学预检”。

## 7. 导入、绑定和预览的连续性

### 7.1 固定入口上下文

创建导入操作时记录：项目、调用入口、目标研究（可为空）、目标步骤/输入槽（可为空）、资料用途意图、客户端操作ID、当前配置修订、用户授权。

用户在接收期间切换任务/项目，原导入不得绑定到后来活动对象。保留原目标并提示完成位置；若原目标或授权已失效，登记/绑定分别复验，保留允许保留的已接收资料并给具体恢复入口，不静默换目标。

### 7.2 持久化要求

成员流式接收/按段校验 → 安全暂存 → 逻辑组包 → 原始资料登记 → 合法任务输入关系 → 显示层登记。

已存字节、逻辑资料、任务绑定、显示就绪是不同状态，但普通UI用简短组合摘要。任何一步失败不冒前后步骤成功，已成功的部分不为另一资料失败全部回滚。

数据资源入口导入不改变研究输入。研究入口明确“添加输入”时自动建立资料输入关系；候选语义不充分的角色映射保留待分配，不将“已加入”冒充方法适用。

资料已经存在且有权限时可复用原件，不因切标签再次上传。同字节不同项目/许可记录不静默合并业务身份。同次操作重试幂等；用户明确新操作不被永久hash唯一约束阻挡。

### 7.3 地图与清单

可靠定位的成功资料自动出图；普通表格先表格。多图层容器登记其实际层/变量并可发现，不能静默只取第一层作为计算输入。任务明确所需层/变量时按该意图绑定，否则只提出候选。

初始定位按本次资料，用户已移动地图后不被后续分组完成反复抢镜头。孤立附件不生成伪地图。安全读取、实际接收及长处理中仍保留关闭和恢复路径。

## 9. 最小内部服务划分（名称为设计建议，不是现有代码事实）

- `InputRequirementsResolver`：按目标/方法/配方/步骤/动作产生版本化需求及替代路线。
- `SelectionInventory`：盘点实际选中或授权范围内的文件，尊重隐私和资源预算。
- `DatasetAssembler`：识别主件附件、匹配候选和组包；处理后补附件版本。
- `CatalogCandidateResolver`：仅查当前授权范围的受管候选，不扫描用户未授权文件系统。
- `ApplicabilityChecker`：技术可读、定位、语义和任务使用分层判断，不混作一个布尔值。
- `ImportCoordinator`：受管登记、上下文固定、逐项绑定、事件/恢复和去重。
- `TaskAwareImportDialog`：唯一导入对话框，用同一状态机显示选择、进行中、需处理和完成，不用多个modal包装。

这些职责可落在现有模块，不要求新微服务或一对象一数据表。前后端类型和支持列表从同一契约生成；扩展名过滤只是选择提示，服务端仍读取实际格式。[R6]

典型接口功能（路径可沿工程统一风格命名）：
1. 获取本次任务/角色的真实输入要求及已有满足项；
2. 创建带固定上下文的导入操作；
3. 提交成员/分段与补充成员；
4. 查询逻辑资料、实际状态和关联候选；
5. 提交明确的关联或解释决策；
6. 完成登记并报告每资料的入库、加入和显示结果；
7. 查询历史未完成操作并继续。

不能只在前端写一串accept后缀就宣布“按任务自动适配”。若读取器不支持某组合，开发状态与用户缺资料分开，不用阻断文案掩盖未实现。

## 10. 安全、预算与恢复

只读取用户选中/已授权范围；ZIP防路径穿越、绝对路径、符号链接越界和解压膨胀；XML禁未授权实体和外部引用；GDAL、VRT、CSVW、STAC等二次读取也走边界控制。识别过程不安装或执行未知代码。

服务器强制单文件、总量、数量、解压、内存、磁盘和时限；界面显示实际限额，不凭扩展名承诺任意体积。目录初扫有界，用户未明确选择大目录全量导入前不开始整盘传输。

异步请求绑定操作ID/任务修订；丢弃过期响应，接收成功不等于绑定成功。依赖改变只使相关检查失效。已导入文件不在每次查看重复hash全文件。

文件/目录选择采用实际浏览器可用能力并测试，不假定showDirectoryPicker在全部浏览器可用；保留多文件、支持的目录选择和ZIP替代。用户授权取消是取消，不显示“格式读取失败”。[R3–R5]

确定性识别、自动组包和规则匹配默认不调用LLM。只在明确授权的文本提取/语义候选场景使用相应能力，候选不自动批准，不将原文件外发给模型猜类型。

## 11. 方法方案编辑：先复现实际动作，再修改

**本节纳入用户本轮指令，不允许只改样式、隐藏红框或全局替换文案。**

### 11.1 两个动作分别查清

定向检查当前实际实例中“保存草稿”和“发布版本”：

| 核查点 | 必须记录的实际证据 |
|---|---|
| 用户触发 | 点击了哪个按钮、当时的编辑状态、当前用户和项目范围 |
| 前端动作 | 实际事件处理函数、请求方法/路径、发送的字段、对应草稿版本 |
| 后端校验 | 实际采用的请求/业务校验及错误映射，不能只看界面标题 |
| 持久化 | 草稿是否写入、发布版本是否创建、批准记录是否改变 |
| 响应与显示 | 状态码、错误字段如何转为用户提示、失败后内容是否保留 |

首先确认截图中的 `TemplateSpec.basis` 错误究竟发生在保存还是发布。不得未经核查就断言两者共用一个校验器，也不得只用“缓存问题”解释。保留修复前的最小复现和修复后的对应验证。

### 11.2 发布限制保留，错误展示必须改变

空方案不允许发布与未完成草稿可保存并不矛盾。必须修复两者的边界和提示，不通过填占位字符、默认权重、隐藏失败或降低校验消除红框。技术结构正确、权限和安全是草稿也必须遵守的要求。

## 12. 方法编辑的固定操作流程与页面

### 12.1 三种新建起点

方法目录显著提供：

1. **从已有方案复制**：建立独立可编辑草稿，记录来源；不修改原方法或共享版本。
2. **导入方案**：使用方法导入入口解析该方案或可映射指标表，建立方法草稿；不误走TIFF主件/附件逻辑。
3. **从零编制**：直接进入方法编辑区，允许先保存空或部分完成的业务草稿。

方案导入以当前实际支持的版本化方法契约及表格映射为准，不以文件能上传就宣称全部规则可执行。未知结构、缺字段与读取失败分别定位；不编造来源依据或科学含义。方法文件及判断/指标表可共用安全上传设施，但领域解析与科研数据导入分开。

### 12.2 编辑位置和结构

复杂方法在现有工作台的中央或可展开编辑区中完成，不再默认使用遮住整个工作台的大弹窗。短命名、确认、资料选择等仍可使用紧凑对话框；不得把完整方法网页再次塞入小抽屉。

顶部只保留：**名称｜草稿状态｜保存草稿｜发布版本**。

主体固定为：

| 区域 | 默认内容 |
|---|---|
| 指标与评分 | 指标选择、实际评分规则及必要参数；默认打开 |
| 赋权方式 | 所选权重方法及其适用输入、参数或判断矩阵 |
| 方案说明与依据 | 用途/适用条件、已有依据引用、必要补充说明 |

不先展示大篇“方法科学依据”文本框。依据不删除，允许按实际能力选择已有依据或补充说明；未实现的引用或导入能力不能只放空按钮。

现有目录继续可搜索、分类、查看、导入、复制与修订。此处是方法编制，不要求重新建立科研任务或上传每次评价的全部原始数据。

### 12.3 空状态

无指标时只显示：

> 尚未添加指标
>
> 从指标库选择　／　导入指标表

不显示“权重合计0”，不在用户尚未触发发布或相关校验时提前铺发布错误。没有实际矩阵或表格时不出现“最大化配置表”。已有表格确需扩大时使用“展开表格”或“展开矩阵”，退出后保留编辑内容。

### 12.4 指标规则必须条件化

指标表作为编辑主体，点击具体行再设置该指标规则。固定定义、单位、评分与赋权各有明确字段，不要求每种方法都填所有列。

| 已选择的规则/方法 | 应出现的控件 | 不应出现的强制项 |
|---|---|---|
| 固定参考评分 | 适用方向、参考上下限或对应曲线参数 | 未选该规则时不强制上下限 |
| 其他评分方式 | 该规则真实需要的拟合范围、分段或类别映射等 | 不通用套用固定上下限 |
| 手工权重 | 当前固定指标身份对应的可编辑权重表 | 不因缺权重自动等权或自动改值 |
| AHP | 指标层次、已存判断/判断矩阵及实际诊断 | 不让用户重复手填由矩阵计算出的权重作为发布依据 |
| 数据驱动赋权 | 实际算法、真实输入契约、拟合范围和适用参数 | 不显示与该算法无关的通用权重字段 |

适用规则仍由实际方法及受支持实现确定；没有依据的科学选项保留待处理，不能为了凑出完整表单自行默认。

### 12.5 编辑状态和布局边界

- 输入内容保存到当前方法草稿，不写进公共已发布方法或历史研究结果。
- 切换三个编辑区域、打开资料选择、扩大矩阵后返回均保留已编辑内容。
- “已保存”由服务器确认后显示；保存中、失败、版本冲突分别表达。
- 不通过CSS隐藏旧错误区或重复表单冒充结构整改。复用选择器、表格和校验服务，不复用完整旧任务页面。
- 不因改方法编辑器重新排列现有主菜单或重建地图/数据源。

## 13. 草稿、发布、批准分别执行和校验

### 13.1 动作规则

| 动作 | 允许与限制 | 成功证据 |
|---|---|---|
| 保存草稿 | 允许业务内容未完成；仍检查权限、有效类型、结构和安全，不接受越权写入或错误类型 | 正确写入可恢复草稿，返回实际草稿修订/状态 |
| 发布版本 | 对指标、适用规则、依据及所选赋权方式的真实条件重新核查；不完整保留草稿、定位缺项 | 原子地创建新的固定版本，不以草稿保存替代发布成功 |
| 批准/认可 | 按真实角色和项目流程执行；不得由普通编辑字段直接授予资格 | 服务器记录指定版本的批准主体、范围和实际状态 |
| 修订已发布方法 | 从固定版本建立新的草稿或修订，不覆盖原版本 | 旧方法、旧运行和结果引用仍保持原身份 |

接口可以拆分或复用现有服务，但以上动作语义必须独立。草稿与发布的请求/领域校验可共享通用字段检查，不能把发布必需内容一律变成草稿保存的必填。

缺少字段与字段类型错误不是同一回事；允许未完成，不等于把任意字符串、对象或越权字段当合法草稿。

### 13.2 批准不再是编辑区通用复选框

移除面向所有编辑者的“认可此方法版本”勾选项。需要批准时提供与权限相符的明确动作，服务器复验资格并绑定固定版本。用户是否能在同一次授权操作中发布并批准，沿用真实项目流程；不擅自新增强制双人流程，也不默认任何编辑者都可自批。

发布成功不自动等于已批准用于正式研究；批准也不等于所有输入都适用。运行前仍要核查本次资料、范围及方法适用性。

### 13.3 未完成与失败场景

- 空/部分草稿可以保存并关闭重开；不自动填“待补依据”字符满足发布字符串长度。
- 发布时没有依据，定位“方案说明与依据”；没有指标，定位指标表。
- 按当前赋权方式检查需要的内容，不将手工权重合计要求强加给未执行的数据驱动参数定义。
- 发布失败不得创建成功版本、删除草稿或清空输入；能显示“草稿已保存，尚未发布”。
- 网络不确定或重试应核实实际创建状态，防止重复发布；不能前端直接把按钮点击当成功。
- 无批准权限者即使改请求/提交批准字段，也不能绕过服务端授权。

## 14. 方法编辑的错误表达

### 14.1 用户提示

不直接向普通界面输出 Pydantic 异常、`TemplateSpec`字段路径、`input_value`、框架错误链接或堆栈。已知校验错误映射到具体业务字段，给简短原因和可定位动作。

| 实际原因 | 默认短提示 | 所在位置 |
|---|---|---|
| 发布所需依据为空 | 请补充方法依据，或选择已有依据。 | 方案说明与依据 |
| 发布时没有指标 | 请至少添加一个评价指标。 | 指标表 |
| 固定参考规则参数不合法 | 显示具体指标及实际不合法参数，例如参考上限须大于下限 | 对应指标行/字段 |
| 手工权重缺项或不满足所选规则 | 显示实际缺项或当前和与要求，不代填 | 赋权区 |
| AHP判断缺少或不符合实际条件 | 显示对应比较/矩阵问题 | 判断矩阵 |
| 保存失败 | 保存失败，请重试。 | 保存状态，保留编辑内容 |
| 发布失败且草稿已保存 | 草稿已保存，尚未发布。 | 发布反馈并定位具体原因 |
| 未知服务器故障 | 操作未完成，请重试或提供请求编号。 | 一条简短错误；受控日志保存诊断 |

上表中的提示只能在真实条件触发时使用。没有输入时不静态挂红框；检查请求失败不能显示“没有问题”。

### 14.2 一处原因、一处定位

同一错误最多一条摘要和一个对应字段提示，不重复两块大红框。技术细节进入受权限控制的日志/诊断，普通界面提供请求编号；不把敏感输入和凭据回显给用户或写入普通前端日志。

服务端校验继续存在；前端是否隐藏、按钮是否禁用不能作为授权或发布检查的替代。修改输入后只更新相关错误，不清空其他有效内容。

## 15. 导入与方法编辑的联合行为

本节是对两份来源中现有规则的连接说明，不增加另一个总体架构。

### 15.1 三种导入意图分别落位

| 入口意图 | 接收内容 | 处理目标 |
|---|---|---|
| 添加研究资料 | 栅格/矢量/统计表/文档等 | 受管资料及本次研究输入 |
| 导入方法方案/指标表 | 方法结构、指标规则、适用依据等 | 当前方法编辑草稿，不自动当科研数据 |
| AHP导入判断矩阵 | 判断值与指标身份 | 指定方法/研究的权重配置，不自动当影像输入 |

可复用上传、安全、表格读取等底层服务，但必须携带明确入口和目标身份。不能只因文件同为CSV/JSON，就复用同一个领域解析分支。

### 15.2 固定方法版本驱动资料要求

方法从草稿发布为固定版本、并满足本次使用所需资格后，才能作为任务正式方法引用。该版本的输入定义、指标配方和算法要求供第2节需求解析使用。

- **浏览或编辑方法不等于应用方法。** 不静默修改当前研究的绑定、要求或结果。
- 用户明确应用方法时，固定目标研究、配置修订和方法版本，计算需求差异，保留仍适用的资料映射。
- 方法还没有完整输入声明时，不让普通用户补内部schema。可以先导入和整理资料；依赖完整定义的科学计算继续受限。
- 新方法版本发布不自动替换已有研究引用；用户明确更换后仅使真正相关的映射/检查和计算节点需更新。
- 普通单位或名称相同不足以证明指标相同；不以匹配成功替代科学适用性核查。

### 15.3 导入未完成时方法/任务发生变化

导入的目标仍按发起时上下文处理，不绑定到后来切换的任务或方法。目标配置已变化时重新核验绑定：已安全入库资料保留，可继续查看；报告“已导入，待重新匹配”或实际错误，并提供恢复动作。

原目标已回收或权限撤销时，依权限分开报告登记与加入状态，不因为另一任务刚好活跃而自动转移。方法修订和后补附件都不得改写历史运行的固定引用。

### 15.4 完整业务仍然连续

正式路径是：**创建/复制/导入方案草稿 → 保存与完善 → 发布及适用批准 → 明确应用到研究 → 提示所需资料 → 导入/复用和绑定 → 原有指标/评分/赋权/综合执行 → 同一运行的真实成果。**

允许先导入资料再定义方法；不建立“没有完整方法就不能导入、没有全部数据就不能保存方法”的循环。两条路径最终在固定研究绑定处汇合。
