# CoastMAS 最少填写与多标准适配设计

**状态：V2业务需求基线，新系统正在实施；未完成全范围验收。** 依据为本轮[report.md](report.md)中的P01–P24及[inventory.json](inventory.json)，不是对历史建议的照抄。保持现有React/FastAPI、受管资产、版本依赖、队列和科学内核；不另建前端、不新增第二套真源，不把普通任务变成标准配置工程。

## 1. 设计取舍和目标

现状已能实际导入大TIFF、运行两个提供的R模型并展示真实样本结果。下一轮应补齐“文件/资产→任务适用输入”的共同层，以及有效信息复用，而不是再次造检查报告或重复实现运行器。

普通操作顺序：**选文件或已有资产 → 自动读取并复用有效信息 → 只处理当前任务需要的缺口 → 预览与执行 → 在同一任务查看结果**。这些是现有工作台中的连续状态，不要求新增五个路由。用户仍可从任意旧入口开始；旧URL、项目上下文、query/hash、返回路径继续有效。

| 发起位置 | 自动带入 | 只询问本次新增内容 |
|---|---|---|
| 数据目录“用于分析” | 项目、选中资产及版本 | 任务与尚未确定的范围 |
| 模型中心“使用此模型” | 方法、模型版本、输入要求 | 适用资料和必要参数 |
| 场景工作台“开展分析” | AOI、场景版本、已有数据 | 方法和任务特有条件 |
| 评价/优化入口 | 任务类型及已选认可模板 | 数据与新增预算/目标 |
| 结果“以此配置新建任务” | 原方法、参数、资料、范围的引用 | 真正修改项；新任务重验，不沿用旧计算值 |

现有工作台采用一致的任务栏（项目/任务/范围/方法/草稿保存状态）、主工作区、按需出现的待处理面板、可展开来源详情和一个当前主操作。已满足阶段直接略过，不强迫五个新页面。填写项仅在“当前任务需要、不能从有效资料取得、不能按认可规则处理、需要人作新判断”时出现。

可合并为“预检并运行”：后端冻结本次配置→重验依赖→生成manifest→幂等提交Job。合并用户动作不合并状态；文件接入、技术质量、模型审批、当前输入适用、工程执行、业务验证分别呈现，旧预检随相关输入/方法/适配计划变化失效。

设计衡量三种量：独立新事实、用户动作、恢复成本。不得用“一次粘贴巨大JSON”降低动作数，也不得把十项科学判断压入一个含糊确认。预计目标必须下一轮实测，以下不是已达成数据：

| 场景/前提 | 建议输入预算 | 必要例外 |
|---|---|---|
| 已识别文件+有效来源/许可与指标模板 | 0个新科学手填，1次文件/资产选择，1次提交 | 文件冲突、许可失效另列，不猜填 |
| 一组同来源同批次文件 | 来源/许可/时期仅声明一次并说明应用范围 | 不同时期/单位/许可的文件分组，不强制全选继承 |
| 现有资产做时间适配 | 选择资产和目标支撑；0次重新填写源值/单位/许可 | 新方法或日历不兼容集中确认 |
| 资产生成评价/优化输入 | 选择认可模板；无须手写矩阵/重复录入候选单元 | 未知方向、成本或保护约束保留必要输入 |
| 已批准模型的新任务 | 选择目标方法、适用输入；复用固定端口及运行包 | 输入不适用不能因先前审批绕过预检 |
| 可恢复错误/页面返回 | 已填有效字段重填0次 | 文件句柄失效仅重新选同文件并验证哈希，不重新填科学声明 |

在相同任务过程避免冗余录入与WCAG 2.2 SC3.3.7一致；安全/必要/已失效的信息有例外。跨任务、跨批次复用是本次产品要求的延伸，不能冒称全部来自该条标准。[W3C说明](https://www.w3.org/WAI/WCAG22/Understanding/redundant-entry.html)

## 2. D01：统一接入和明确复用（P01、P13）

**落点**：`DataImport.tsx`、`DataWorkspace.tsx`、`DataMetadataForm.tsx`、`app/ingestion_routes.py`、`core/file_ingestion.py`、`core/data_inspection.py`，复用现有对象存储及ResourceVersion。

普通入口统一为“添加数据”，接受文件或已有批准来源。先查真实字节/容器/图层，不先让用户选择数据类别、格式、CRS和所有变量。原声明上传作为兼容/专家入口保留；已有表单值作为候选声明参与验证，不能覆盖文件事实。

1. 建立接入批次，逐文件计算哈希、保存原字节、限额与安全检查。部分失败逐条报告；成功项不回滚成“都没导入”。重复提交使用幂等键。
2. 检测文件标准候选和版本证据；扩展名只作线索。确定的自动选取；真正歧义只问一次，不弹出全部标准菜单。
3. 显示“已读取”“沿用来源”“待补充”“不适用于当前任务”。缺科学说明允许受管登记和预览，不能因此放行正式计算。
4. 同项目同字节先展示已有资产与当前声明/版本；默认复用可读且适用的对象。确有新用途可显式创建新资产关系，不按哈希静默合并不同许可/所有权的记录，也不泄露别的项目已有文件。
5. 接入后留在工作台；直接选择“建立实体/时间适配/准备模型输入/评价/优化”，带上固定资产引用与已确认映射。不是返回目录再复制ID。

**拟契约**：现有`POST /data-assets/ingest`和`ingest-local`保持兼容；新`IngestionSession`记录文件项、进度、解析facts、版本化声明与问题。拟新增会话创建/检查/完成接口，旧客户端由兼容层走相同服务。默认检测不得更改原文件；上传限额、内存读取限额、计算限额分开显示。批量与续传的上限由后端强制，非无限承诺。

**失败/恢复**：中断只续未完成文件；同哈希检查后复用已完成部分。报告指出实际失败阶段及已保留资产，不能只给通用“上传失败”。不清理历史证据。验收见B02。

## 4. D03：事实、声明、语义与任务适用分层复用（P03、P06、P17、P23）

复用已有asset quality/lineage、VariableSpec、BindingPlan与版本依赖；补充同一套结构，不能再维护“报告里的另一份注册状态”。

| 层 | 拟增加或明确的内容 | 真源/复用与失效 |
|---|---|---|
| FileFacts | 检测器版本、文件/图层/变量路径、原始属性、hash | 从字节提取；原文件变化失效 |
| Declaration | 值、声明者、依据、适用文件/列/时期、精度与未核实状态 | 用户/资料方声明独立保存；不可写成文件事实 |
| SemanticBinding | 源字段→词表概念/版本→单位/支撑/类别映射；批准范围 | 资料与科学负责人认可；超范围不自动复用 |
| MethodProfile | 算法/标准依据及版本、参数/前提、合法输入、输出含义 | 方法维护者认可；权重/阈值变更新版本 |
| Applicability | 针对当前资产版本×目标方法×空间/时间范围的检查结果 | 每次运行重验；审批不等于所有输入适用 |

复用分三层，不能把全部条件塞入同一个严格键，导致新文件让所有知识失效：

| 层 | 固定身份/适用性 | 新批次行为 |
|---|---|---|
| 文件事实缓存 | 字节hash、解析档案/版本 | 字节或规则变更则重新读取事实 |
| 认可语义/方法模板 | 模板及版本、权威依据；校验结构、概念、统计支撑、空间/时间/许可范围和访问权 | 适用条件仍成立则引用原知识，不因新hash要求重填 |
| 本次任务绑定 | 具体资产/字段/版本、模板/方法版本、参数与任务范围 | 新数据生成新绑定并重验，不能复用旧计算值 |

名字相同不足以证明适用；新文件也不必然使认可字典失效。首次缺说明时自动生成变量映射表：源文件/变量、真实预览、科学概念/类别字典、单位/支撑、依据/范围、状态。允许从认可说明文件、标准元数据或模板匹配，由负责人集中处理缺口；所有下游引用同一说明，不要求编辑内部JSON。

文件中记录的单位也可能有误，读取到值不等于科学核实。文件事实与声明冲突时并列来源，以依据支撑纠正和版本变更；不存在“文件永远正确”或“用户总覆盖文件”的优先级。

无损确定性操作（精确单位换算、已认可字段别名、一致日历下格式转换）自动生成计划并记录依据。不同垂向基准、重采样、类别合并、时间聚合/缺测填充、方法/权重变更可能改变解释；在一次“影响说明”中列原值、目标、损失、有效范围并确认。一个确认包可以多项，但每项决策可追踪，不能含糊一键接受未知科学假设。

缺依据只阻断依赖它的动作：TN无法定位仍可保留原文件和非空间检查；缺响应不阻止无监督聚类的工程适配；缺评价方向不阻止文件接入。原业务A/B/C含义和科研实验A/B/C分组不可混同。所有临时工程夹具带醒目标记，不进入正式模板库。

拟补`mapping_ref`/`method_profile_ref`/`declaration_refs`与`unresolved_requirements`；旧内嵌字段继续读，展示为“历史显式声明，未迁移认可”。不批量猜填旧数据。见B04。

## 5. D04：版本化能力档案和普通自动适配（P04、P05、P19、P22）

**落点**：`data_inspection.py`、`file_ingestion.py`、`source_routes.py`、现有单位/空间适配内核和validation；新增最小有类型的`FormatProfile`/`SemanticProfile`能力注册表，供检测、UI、预检、导出共用。不得让UI与后端各维护一份支持清单。

普通界面默认“标准适配：自动”，只在真实歧义时展开选择。文件/容器、变量/时空语义、科学/行业方法、成果/接口是四个不同层次；换编码不等于换评价体系，后者必须生成新的方法配置。

每项能力按`标准名+规范版本+扩展+解析器版本+阶段`声明。阶段分：识别、结构校验、语义提取、映射、任务使用、导出、信息损失。阶段状态必须能表示部分支持和不支持；版本未知不强标最新。资源version、契约schema_version、词表version、方法版本分别记录。

| 档案候选 | 自动行为 | 必须显式处理的边界/测试 |
|---|---|---|
| GeoTIFF / COG | 读取grid/bands/NoData/scale/offset及单位属性；区分COG布局 | 物理值与原始值域不能混同；COG符合性与HTTP Range单独测试，不能凭TIFF可读宣称支持 |
| GeoJSON RFC7946 | Geometry/Feature/FeatureCollection识别；稳定ID/属性/几何映射 | legacy CRS、Z维/空几何有明确能力说明；不悄悄丢弃第三维 |
| GeoPackage版本档案 | 读应用/用户版本、图层清单，保留原包 | 多图层自动列出可用对象；选择应按任务需要，而非静默取第一层；扩展/关系不支持时报告影响 |
| Shapefile ZIP | 校验配套文件/路径/编码；字段别名建议 | 字段名截断/编码冲突、缺prj集中处理，导出有损预览；不根据地名猜CRS |
| CSV方言/CSVW | 检测BOM、编码/分隔符候选；可信metadata读取类型/缺值/列语义 | 逗号小数、引号、多行、时区、ID前导零、日期精度；歧义才选择方言，单位无依据不补 |
| NetCDF / CF档案（明确版本） | 保留axes、coordinates、grid_mapping、units/calendar、bounds、cell_methods、packed值与missing | 360_day与Gregorian不可直接当同一时间；不支持日历时明确禁止相应适配，仍可登记/预览 |
| STAC Item/Collection及扩展 | 发现assets/时间/空间/链接，继承有依据的扩展信息 | URL权限/SSRF/认证、资产多样性、扩展版本、缺失许可；不要把普通HTTP快照称STAC支持 |
| CoastMAS JSON/YAML领域数据 | 检测schema标识和版本，读取frame/模型/场景等实际结构 | 无schema的JSON只可受管/预览，不猜其为评价矩阵；未知schema保留原文件并解释缺映射 |
| 词表、CRS与单位 | 明确权威标识/词表版本；复用已有PROJ/Pint核验 | 词近不等价；垂向基准、总量守恒与类别重采样方法不能无条件转换 |
| 方法标准/模板 | 仅将认可方法作为可执行档案；选择任务自动过滤适用版本 | 标准更新不自动重算/覆盖旧结论；并排说明新旧适用前提和结果不可比因素 |

这些是目标能力，不是本轮支持声明。具体支持子集以每阶段夹具与反例证明；适用标准之外的扩展保留信息/明确拒绝，禁止“支持全部版本”。OGC API Processes是已有任务接口可评估的互操作适配层，见B13；保留自有API，不强迫普通用户选协议。

`AdaptationPlan`拟记录源与目标档案、steps、确定性、可逆性、损失、confirmations、受影响操作、源/实现哈希。执行仍进入现有任务/worker，输出登记新派生版本和依赖；原字节可下载。标准化导出携带方法/单位/范围/许可和来源侧车，不能只导出无说明数值。

兼容迁移：只添加可选版本与引用；旧资产按原代码路径解释并标“旧档案未知”，再次参与新任务时生成检查建议。禁止自动改旧manifest、旧结果或把新解释追写为历史事实。见B05。

## 6. D05：一个资产映射层服务全部下游（P07–P09）

复用`prepare-raster-frame`与评价`prepare`的有效部分，建立共用`ObservationMapping`，输出仍是现有各内核契约，不让用户亲自拼内部结构。

映射可识别源列/变量、实体键、几何、时间轴/支持区间、数值、单位、类别和缺测；保存固定源版本、模板版本、行身份及匹配错误。重复实体×时期、缺失键、混单位、轴对不齐不能默默平均/舍弃。所有行的状态/分母可核对，预览有界而执行范围明确。

| 当前页面/接口 | 增量交互和边界 |
|---|---|
| `Entities.tsx` / `/entities` | 从资产选择图层/几何与实体键；批量校验预览后建版本。有效时间按数据含义声明；记录创建时间与观测有效期分开，不默认今天即数据有效日。单体手绘继续保留 |
| `TemporalAdaptation.tsx` / `/adaptations/temporal` | 从资产或场景变量选择；预填源观测/单位/许可/支撑，用户只选目标尺度和必要方法。日期控件按支持日历显示，不能把360_day硬塞Date |
| `IndicatorFrameworks.tsx` / `/indicator-frameworks/{id}/prepare` | 从列或栅格映射认可指标体系；公式输入从候选选择，引用固定版本；保留已实现的单位换算/空间支撑/样本范围，不补猜方向 |
| `SpatialOptimization.tsx` / `/optimizations` | 选择管理单元资产，把ID/面积/成本/风险/保护标记映射后生成OptimizationFrame；由用户补实际预算/目标。缺成本不能填0、受保护单元不能用默认可选掩盖 |
| `SceneWorkspace.tsx` / 现有场景资源接口 | 从选择资产提取可用范围并推荐AOI/时期；推荐不等于所有变量公共覆盖。用户选研究范围，显示交集/缺口，不静默裁剪 |
| `Planner.tsx`、`WorkflowEditor.tsx` | 从任务带入固定场景/源/方法；可靠绑定自动完成；只呈现不确定/不兼容处。高级工作流节点编辑保留 |

场景普通入口不再展示任意“新增字段名”：实体类型和所需成果用目录多选；目标网格用“与哪份栅格对齐”；时间按真实年份/日期/时点/区间精度呈现；情景条件、缺测和转换策略仅展示目标方法实际需要的领域控件，带单位与依据。方法未知时不先要求填写无限扩展字段组；专家编辑和旧字段仍保留。

普通评价者选择认可体系与版本并处理不匹配项；首次建立方法的公式/方向/阈值/权重由方法负责人维护。普通模型入口“使用此模型”取得固定输入槽和参数；新增端口与运行配置保留给维护者，不作为日常分析前置。

拟在相关请求增加可选`source_refs`和`mapping_ref`，保留旧显式输入接口。服务端生成规范内核对象并返回逐字段来源/转换说明；请求不能同时给冲突的显式值和映射值却静默择一。旧入口展示改造继续核对原提交语义；新增mapping_ref请求不要求与旧JSON字节相同，须核对服务端解析后的科学值、约束和来源及实际结果。见B06/B07。

## 7. D06：范围明确的模型准备与全图计算（P10）

`RasterFrame.tsx`先选择任务/已批准方法，再展示输入槽、特征和响应需求；不以是否填响应隐含改变用户意图。候选资产先按项目/适用性过滤并支持稳定搜索，已选项目跨分页可见。

现有显式样本/有限全量链路保留。采样显示种子、总体像元/共同有效分母、选取规则和位置；标准化的均值/方差与训练范围冻结。全图能力另作真实工程任务：读取窗口和产物分块不等于算法可独立分块训练。PPCI先明确聚类训练及全域赋类规则；pprRFA明确训练/验证与预测流程，不能把每块独立拟合拼成等价全图。

内存上限、取消/恢复、阶段产物、写出掩膜、像元身份与数值对照都须验收；不把10000上限偷偷提高当完成。源不同网格的适配必须由D04计划说明目标网格和重采样科学含义。见B08。

## 8. D07：跨页任务上下文、草稿与恢复（P11、P21）

现有路由继续有效，用最小`TaskDraft`关联当前项目、目标、源引用、未确认科学项和编辑内容。跨页、刷新、关闭后重开均属于必需恢复能力，采用**项目内服务端持久草稿**，与第一条少填链路一起交付。草稿仅保存必要编辑内容和引用，不存原文件字节、大矩阵、密码、token或连接器凭据；继承项目访问权，并明确草稿访问者、保留期限和删除规则。本机仅存非敏感偏好/草稿引用，不能用仅同会话恢复替代持久能力。

返回/刷新恢复前重新校验权限与源版本。源已变显示差异，只要求处理受影响项；不重置无关输入。文件重选验证同hash后继续。离开仅在确会丢失不可恢复修改时提醒，不能每次翻页都确认。

运行仍使用现有Job状态机、manifest、幂等键、取消/重试与租约逻辑；草稿状态不冒充Job状态。网络失败自动重试幂等读，写操作通过幂等键避免重复资产/任务；按错误层保留输入及一键回到修正处。见B09。

## 9. D08：统一模型状态解释与职责（P12、P15）

`ProvidedModels.tsx`、`BusinessIntake.tsx`、模型目录与结果详情共用状态投影：源码已发现→技术包已验证→项目运行版本已批准→当前输入适用→工程执行有证据→业务结论有依据。不得合成一个含糊“已验证”绿勾。

本地报告离线读取时明确“检查时刻的源码信息，不代表当前项目登记/审批”；用户选择关联项目后按源包hash/受信release查询实际状态，不上传报告冒充数据资产。无匹配显示未知，不强配名称。

保持现有审批权限：提供模型审批使用**项目admin**，系统账号/成员管理使用系统管理员规则；不改后端来迎合菜单。批准固定运行版本后普通任务不重复审批同版本，但每次科学预检仍重算。技术依赖/适配器工程归开发维护者，科学定义归业务方，两者阻塞原因分开展示。见B10。
