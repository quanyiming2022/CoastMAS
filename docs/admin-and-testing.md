# 管理员与测试环境

系统管理员登录后，侧栏显示“系统管理”。已有管理员账户由私有配置初始化，不在文档或提交记录中保存口令。

管理员可管理账号启停、全局管理员身份、密码重置、项目及项目成员权限，并查询审计记录。密码重置撤销旧登录会话；最后一个有效管理员受到服务端保护。所有管理操作仍由服务端鉴权，隐藏按钮不替代权限检查。

项目归档只控制常规工作区的可见性，不删除模型、数据、场景、运行、成果或历史版本，也不撤销成员权限。管理界面可恢复项目。需要撤销访问时应修改成员权限或停用账号，不能用归档代替权限管理。

中国典型海岸真实影像项目包含三个公开影像演示。原合成测试项目与首次校准冲突的影像项目已归档；自动化测试、科学金标准和历史验收证据保留。

## 普通自动化浏览器测试

```sh
.venv/bin/python scripts/e2e.py
```

入口创建随机命名的临时PostgreSQL数据库、MinIO桶、Redis键前缀、独立API/worker/beat与本机HTTP数据源，使用私有临时账号。无论测试通过或失败，退出时仅清理本次创建的资源，运行日志和失败浏览器记录保留在忽略提交的artifacts/runtime目录。不会使用日常工作区作为测试夹具。进程被强制杀死时可能遗留随机测试资源，需要按该次日志核查后清理，禁止清空共用数据库或Redis。

普通Playwright配置从环境读取COASTMAS_E2E_URL和COASTMAS_E2E_ACCESS_FILE；请使用上述入口。它明确关闭规划LLM以验证无外部凭证的确定性功能。生产配置COASTMAS_LLM_ENABLED默认为true；设为false时不创建提供方客户端。POSTGRES_DB和COASTMAS_QUEUE_NAME分别选择服务数据库与队列，默认保持原运行配置。

## 真实演示现场验收

```sh
npm --prefix apps/web run e2e -- --config acceptance.config.ts real-imagery.spec.ts
```

该测试访问已部署的本机系统和真实影像项目，验证影像与互联网底图。需要已有私有访问配置、已发布影像及可用互联网。网络失败如实报告，不替换成模拟通过。

`acceptance/admin-cleanup.spec.ts` 是针对本次已授权清理的显式维护验收，会归档文中两个固定旧项目，保留历史。不要把它放进普通自动化测试或对任意用户项目运行。管理员其他功能由集成测试与前端组件测试覆盖；未逐项实测的界面操作不能宣称已通过真实浏览器验收。
