# 实施决策

1. 沿用任务书模块化单体方案；采用单主执行者，没有重复代理审计或源码复用。
2. 版本化领域对象由共享 resources/resource_versions 保存，权限、引用和当前版本是关系约束；不可变版本和审计由 PostgreSQL 触发器保护。地理实体另有不可变 PostGIS 空间索引；图谱从这些资源契约生成有界 NetworkX 视图，避免第二份可漂移真源。指标对象仍需继续补齐。
3. 早期磁盘满时曾使用项目专属内存盘测试容器；用户扩容后，当前集成测试在本项目持久 PostgreSQL 实例中创建独立临时数据库，执行升级—降级—升级后销毁各自数据库，不降级主数据库。完整部署门禁仍未通过。
4. PythonFunctionAdapter 仅序列化维护者在进程内注册的受信函数，在私有临时目录启动独立子进程。不得上传 pickle 或让用户填写任意模块路径。CLI 仅使用注册参数数组、关闭 shell，并对整个进程组执行有界终止。
5. SQLAlchemy 服务函数由调用方控制事务；API 在返回成功前显式 commit，防止响应成功后才触发延迟外键失败。
6. 不吞掉质量失败：单元、类型、规范、真实数据库、环境失败均保存在 evidence；通过部分测试不表示完整范围已验收。
