# 空间优化研究示范

入口为「空间优化」。SpatialOptimizationModel 是注册的可执行 MILP 模型，输入文件、场景、模型、工作流和结果都有固定版本及来源记录。计算运行成功和优化问题可行是两个不同概念。

## 输入及操作

新建配置，选择基础场景，填写候选单元的标识、收益、成本、面积、生态成本、风险指标与是否允许选择。所有列需要明确单位；预算/生态/风险上限沿用对应列单位，面积下限沿用面积列单位。填写非重叠面积和指标可加性的科学依据。风险在这里是可加的惩罚指标，不是直接相加的概率。未知单位、重复标识、布尔伪数值、非有限值、非正单元面积、负成本和负边界被拒绝。

「载入合成示范」显式填入 SYNTHETIC 数据和假设，用于验证，不宣称为真实管理资料。成本/收益等示范指标无量纲（单位 1）；货币或其他自定义指标必须有明确的单位和依据，不能输入未知单位绕过校验。

保存会写入经过实际检查的 JSON 文件及 SHA，追加数据目录版本，并从所选场景复制一个独立固定场景。原场景的范围、时期、条件、硬约束和实体引用保留；仅新的管理目标和要求输出改为优化任务。该输入表示整个已声明决策期，其时间支撑为场景起止差的实际秒数，不伪装成逐日观测。原场景不会被覆盖。

配置创建、文件/场景/工作流引用及审计在一个数据库事务内保存。项目/用户/幂等键固定身份，重复同一请求返回原记录，修改参数后复用旧键拒绝。文件使用项目内的内容寻址键；文件已写但数据库事务失败可能留下未引用对象，后续孤立对象回收仍待统一实现，不假称文件和数据库跨系统原子回滚。

预检通过后提交到既有 PostgreSQL→Redis→独立 worker 通道。实际执行再次检查不可变快照、权限、SHA 和可信运行签名；超时、取消和结果发布沿用统一执行设施。修改条件需创建新的固定配置，不覆盖已运行输入。

## 数学与科学范围

对每个候选单元求二元变量 x，最大化收益之和：

- 成本总和不超过预算。
- 面积总和达到明确下限。
- 生态成本总和和可加风险总和分别不超过上限。
- 不允许选择的单元，或输入 `protected_unit_ids`、场景 `optimization_protected_units` 中的单元，其 x 必须为 0。

场景保护清单中的标识必须出现在候选集中，否则拒绝，不能悄悄忽略。场景保护不能被上传的 `allowed=true` 取消。保护是硬约束，百万收益也不能抵消。

面积使用 Pint 转换到平方米，面积边界同步换算；其他各列及相应边界在各自明确的同一单位内比较。复用 SciPy/HiGHS MILP，求解后重新验证有限性、二元取值及每条硬边界。现有求解校核的绝对数值容差为 1e-7（在每条边界所报告单位中）；实际值和边界均保留，不裁剪成虚假的恰好满足。

单次输入至多 5000 单元，求解时间 0.01–120 秒，工作流超时留出进程启动和收尾时间。结果区分 OPTIMAL（最优）、INCUMBENT（已验证可行但未证明最优）、INFEASIBLE、TIME_LIMIT 和 FAILED。无可行解时 totals、分配标记和约束实际值是 null；不能将空选择解释成全部未选。结果保留求解器消息和实际报告的相对间隙，始终 `policy_decision=false`。

这是明确可加假设下的二元分配示范，不自动推导政策权重、空间邻接/连通性约束或候选面积的正确性。面积来自输入声明，必须由数据准备保证互不重叠；模型不凭地图图形猜测收益、成本或保护政策。

## 空间与追溯

每个候选输出独立 ResultObject，保留输入标识、实际选择值、允许标记、面积和指标单位，以及实际结果文件中的来源指针。候选标识与固定场景实体的 management_unit_id 对齐后绑定精确实体版本，在既有结果中心查看地图和完整输出；没有匹配时如实标为 UNBOUND/PARTIAL，不能假称已定位。

OptimizationSpec 固定 source_scene、scene、data、workflow，通过 ResourceDependency 精确版本外键保留来源。数据与派生场景也引用原场景，来源被引用时归档返回冲突。场景归档接口已补齐并保持重复请求幂等。记录归档保留历史，阻止新运行；旧任务与结果不删除。
