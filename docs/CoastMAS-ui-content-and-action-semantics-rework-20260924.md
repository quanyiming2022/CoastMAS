## 0. 问题与本轮边界

### 0.1 已知表现与证据边界

用户提供的截图中，当前研究输入为0、运行记录为0，但“资料装配”面板同时展示：作用范围/当前草稿、当前草稿配置版本、尚未选择资料、修改只保存草稿、实际输入引用、当前草稿预检缺口、检查草稿缺口、当前查看的运行产物、没有文件产物、最大化配置表及返回任务等内容。

可确认的问题是：正常空状态承载了过多内部结构与跨步骤说明；操作按钮没有直接说明用户将完成什么；已有全局信息在每个步骤重复出现。截图不能证明具体组件、接口和按钮实际上怎样实现，需定向追踪后再修改，不能仅凭按钮名称声称后端不存在某功能。

### 0.2 本轮目标

- 普通用户能快速回答：现在有什么、需要做什么、完成后会得到什么。
- 已经由系统保证的行为，不再写成每页常驻免责声明。
- 正常状态简洁；错误、缺少必要信息、版本不一致和风险发生时准确出现。
- 所有标签与按钮对应真实对象和实际动作，不把后台键名、通用接口术语直接显示。
- 输入/任务/步骤/方法/运行/成果不串状态，数据查看与科学计算保持区别。

### 0.3 保持不变

继续桌面优先、完整中文主菜单、中央可视工作区、左侧图层/输入/运行、右侧八步流程，以及可上下拖动/最大化/恢复的底部目录。项目、用户、系统设置各自职责保留，不为本轮重排菜单或恢复聚合长表单。

权限、来源、固定版本、历史成果不可变、真实算法、幂等执行、服务端草稿、错误恢复和标准适配仍需完整。没有旧UI、旧提示语、旧私有接口兼容义务，但不为了改文案重写正确内核。全局“真实执行、少填、少重复”要求继续有效。

## 1. 把三种文字分开

| 内容类别 | 使用场合 | 规则 |
|---|---|---|
| 用户操作文案 | 页面、字段、按钮、状态、必要错误 | 使用业务对象和明确动作，简短且准确 |
| 方法与帮助说明 | 用户主动展开、首次确需理解的选择、方法详情 | 说明依据/限制，不占所有页面的首屏 |
| 工程实现与诊断 | 代码、接口、测试、日志、开发者技术详情 | 保留严谨性，但不能原样作为普通操作说明 |

“历史运行不可变”是系统必须保证的规则；普通编辑页无需反复写“修改不改写已有成果”。只有用户正在看历史结果同时编辑新配置时，显示一句“当前结果来自配置第4版；你正在编辑第5版”等实际差异。

这不是把难懂文字全部移入tooltip。用户完成当前操作所必需的信息必须直接可见；完整来源、技术诊断和帮助允许按需展开，并支持键盘访问。

## 2. 四类呈现位置

### 2.1 正常工作区域

只包含本步必需输入、真实选择器/编辑器、简短状态和主要动作。已有事实和已确认值用摘要复用，不要求重复确认。无相关内容的区块不预留空标题。

### 2.2 当前异常

失败、必要缺项、版本不匹配、权限变化等显示在相关资料/字段附近；阻断本次操作时提供紧凑汇总，按根因去重。提示对象、原因和可执行的修复动作，不以一段原则宣言代替错误。

### 2.3 高影响决策

覆盖草稿、移除被使用的输入、回收对象、公开发布、有损转换等，在实际动作发生时给必要影响说明。明确选择已经足够的普通操作不再重复弹确认。

### 2.4 来源与技术详情

原始属性、哈希、完整运行ID、请求ID、JSON/schema、解析日志、有效声明、转换依据等放详情。技术字段保留准确标识，复制和授权检查仍有效，不删除后台证据。

## 4. 两个可疑按钮先核实，再决定保留方式

### 4.1 “检查草稿缺口”

先追踪实际handler、请求和服务端副作用，确认是否仅计算输入/配置要求。若当前已绑定版本的轻量检查能够自动执行：

- 在资料加入/移除、方案应用、必要设置保存后按依赖更新，不要求先按“检查”才看到缺什么。
- 使用已有元数据和已保存引用；合并连续修改，取消/丢弃过期请求，检查结果绑定准确配置版本。
- 没有任何输入时，空状态本身指出“添加资料”，不额外制造一份重复缺口清单。
- 正常编辑不触发全图统计、模型训练、外部收费请求或无限轮询。
- 昂贵检查单列真实动作、范围和代价，不伪装成一次轻量检查；若有确定的缺少条件，不昂贵试跑来发现它。
- 正式提交运行时服务端仍再次执行必要校验。移除手工检查按钮不等于删除服务端预检。
- 网络失败显示“检查未完成”及恢复入口；不能把错误当成空问题列表。
- 检查本身不新建研究任务、不提交计算作业、不把阶段标为已完成，不改变科学输入。允许写入有来源的检查结果缓存，但不覆盖用户配置。

若实际功能与上述不同，先说明真实动作并按动作命名，不能为了迎合文本偷偷改语义。

### 4.2 “最大化配置表”

核查它实际是改变Dock高度、打开指标矩阵，还是把旧长表单换个容器。如果没有表格，不能只保留一个听起来有功能的按钮。

- 大型指标表、判断矩阵、年鉴对照确实需要展开能力；显示“展开表格”或“展开矩阵”。
- 普通两三个字段的步骤不出现展开按钮；整体编辑器扩展则明确“展开编辑区”。
- 展开/恢复保持草稿、行选择、滚动、焦点、地图及运行引用；不导航到重复旧任务网页。
- 不为显得专业新增另一套“配置表”数据模型；前后视图读同一字段和状态。
- 未保存变更的真实风险继续提示；服务器已保存的正常切换不反复确认。

## 5. 第1步的最小真实设计

### 5.1 没有输入时

标题：资料装配。

内容：“尚未添加输入资料”。

主动作：“添加资料”，打开统一资料选择/导入界面，支持“从资料库选择”和“导入新资料”。

格式提示仅在选文件的操作区显示实际支持格式，不能在整个研究面板重复列全部格式。来源许可等在相关资料或实际使用需要时处理。

不显示：作用范围下拉、空的引用标题、零运行产物说明、无内容表格展开按钮、详细版本故事及三段重复空状态。

左侧已有“输入0”和添加入口可以保留为工具栏，但本步骤的首屏只突出一个主要行动。同一服务处理两个入口，不建立两份上传/输入集合。步骤面板打开时，中央空白区不再重复长段说明和另一个大按钮；面板关闭或无活动任务时，中央允许提供一个导入查看入口。

### 5.2 有资料且没有本步问题时

标题：“资料装配”。紧凑输入列表显示真实名称、类型、读取状态和必要操作。“添加资料”仍可用。

文件元数据可读但后续评价语义尚不齐全时，不谎称“可运行综合评价”；也不把后续全部权重/评分问题一次堆到本步骤。任务整体未满足条件时可在全局执行入口提供可定位摘要。

“已读取”只表示读取，“已加入”只表示输入关系；没有校验数据时不硬写“已就绪”。

### 5.3 有真实问题时

一行问题例如：“影像与定位附件不一致。” 主操作“核对定位”。记录关联资料，完整冲突参数展开查看。

`.tfw/.aux.xml/.ovr`先按真实角色组包，不能继续被当普通表格或独立指标；本轮不只把“表格方言错误”改成好听的错误而保留错误解析链。

一项问题影响多个步骤时，主问题记录唯一，当前步骤展示其相关动作；全局汇总给出影响步骤，不重复弹多次。

## 6. 八步按业务说话，不用同一“缺口/产物”模板覆盖

| 步骤 | 主体内容 | 主动作示例（仅对应实际实现） | 不应常驻的内容 |
|---|---|---|---|
| 1 资料装配 | 输入资料和导入问题 | 添加资料 | 尚未运行的成果说明、权重要求 |
| 2 空间统一 | 参考网格/目标单元、实际差异 | 生成对齐数据；无需转换时短状态 | 重复上传全部文件、未经确认的默认CRS |
| 3 统计空间化 | 年鉴表、边界匹配、适用辅助数据与方法 | 关联到行政区/计算空间化 | 把自动落图叫作统计空间化、所有方法的字段全展开 |
| 4 指标生产 | 指标、资料来源或配方、实际进度 | 计算待生成指标 | 每个源字段都填响应/解释变量等无关角色 |
| 5 指标标准化 | 评分方向、方法、参考或拟合域 | 生成标准化指标 | 再填文件格式/来源；将显示色带叫评分 |
| 6 权重配置 | 指标身份、已选方法、判断/拟合与权重 | 计算权重/应用已有权重 | 再上传第5步结果；假设权重默认有效 |
| 7 综合计算 | 固定指标与权重、范围、实际阻塞与输出 | 运行综合评价 | 再重建一张资料输入表，或只有下载按钮 |
| 8 验证交付 | 实际检查、适用验证、结果和导出 | 运行所选验证/导出成果 | 缺独立验证就显示假通过，或无意义“尚无产物”填满页面 |

普通短标签必须可查看全称，尤其“统计空间化”不得重命名为“落图”造成语义错误。保留全部业务能力，不以简化界面删除工具或独立分析任务。

## 7. 全站盘查范围：一次全覆盖，后续定向读取

### 7.1 覆盖的界面

登录与账号会话；项目选择；研究首页；资料/图层/输入/运行面板；八步流程与所有条件分支；分析配置；数据导入/组包/预览/映射；任务/资料/方法/模型/运行/成果目录；方法新建/导入/修订；模型包接入/验证/发布；导出、图件、比较；项目/成员、用户、数据源与设置、审计、回收站；所有对话框、提示、空状态、toast和共用详情。

前端路由、组件、统一文案及后端提供的面向用户错误/状态是范围。不能只修截图里的一个panel。截图能发现文案问题，准确副作用需读对应处理和请求证据。

### 7.2 状态也要覆盖

无当前研究、0输入/0运行、已保存、保存中、离线未同步、保存失败、并发冲突；无匹配、无权限、服务失败、未知信息、实际缺项；检查中、排队、运行、取消中/已取消、失败、部分完成、成功；历史结果与当前配置不同；项目/任务/单个资源回收或归档；多图层/大目录/长名称；真实业务与工程示例；管理员与普通分析者。

0条输入不代表资料库空；0运行不代表写出失败；0条检查问题不代表检查已成功；表格产物不代表没有结果；未知数量不能填0；后台状态暂时未知不能直接写“已成功/已取消”。

### 7.3 具体方法

1. 固定当前用户实际访问的构建、项目和可复現对象；先记录而不是归咎浏览器缓存。不修改正式数据来取得漂亮截图。
2. 列一次界面/状态覆盖表，并对相关代码进行一次定向字符串扫描：草稿、引用、缺口、产物、固定运行、只读检查、真实/实际、SHA、schema、保存/不覆盖、最大化等仅作发现线索，不设无脑删除黑名单。
3. 每条发现记录：页面/角色/状态、原文本、组件或API来源、真实动作/副作用、是否重复、处理类别、替代文案、出现条件、验证用例。
4. 处理类别明确为：保留必要/改业务名/移至详情/合并重复/仅异常时出现/改交互/删除无关展示。删除展示不删除后端规则。
5. 先修改共用问题列表、空状态、保存状态、结果摘要、面板标题和展开控件，再回到各业务分支核查特有条件。共享组件不能把不同业务强行压成同一语句。
6. 审查当前按钮handler和服务端用途；确认功能后再命名。如果按钮空实现或行为有误，修复/如实标不可用，不靠改名验收。
7. 不读取/输出无关全库内容，不每改一个页面重新扫描整个仓库。使用一个简短状态文件与一份覆盖/证据表。

建议覆盖表字段：`页面 | 状态 | 角色 | 组件/API | 原文/动作 | 问题 | 处理决定 | 新文案 | 触发条件 | 实测证据`。

## 8. 统一词汇：有上下文，不做全文替换

| 内部表达/含糊表达 | 普通用户表达示例 | 不能丢的区别 |
|---|---|---|
| input_refs | 输入资料 | 地图参考图层不等于输入 |
| draft | 当前配置；新方法生命周期中仍可用草稿 | 编辑中配置不等于已运行配置 |
| unresolved_requirements | 待处理/具体缺少项 | 未检查、检查失败、真无缺项分别处理 |
| artifact | 结果/成果文件；本步骤自己的中间产物叫处理结果 | 原件、预览、指标与综合结果不混同 |
| freeze config | 不必常驻展示；详情“本次使用的配置” | 正式运行仍固定版本与来源 |
| schema/hash/internal ID | 技术详情 | 原值和身份完整保留，不改变API键或用户自己的字段 |
| succeeded | 计算完成 | 不等于显示就绪或正式业务通过 |
| 未取得运行文件但有表格 | 展示实际表格 | 不是“没有结果” |
| 回收/删除/移除 | 使用实际动作词 | 移出地图、移出输入、回收记录、物理清理分开 |
| 作用范围 | 按真实语义命名 | 不能把编辑对象、研究空间、统计区混为一类 |

新文案写在已有前端文案层或轻量有类型的目录中，按需要统一；不为中文清理新搭大型国际化系统。参数化文案使用实际对象名和数量，未知信息明确不补。不能修改用户文件名、指标名、代码列、方法原名、原文引语和不可变审计数据来通过扫描。

## 9. 错误与反馈：短而可操作

格式建议：`对象或上下文＋具体原因`，旁边一个最有用的修复入口；技术细节另开。默认一到两行是排版目标，不是剪掉安全信息或长对象身份的硬字符上限。

| 情況 | 用户提示 | 操作/限制 |
|---|---|---|
| 当前任务没有输入 | 尚未添加输入资料 | 添加资料；常规空状态，不红色报错 |
| 资料成功绑定 | 已加入研究 | 更新输入数量与行状态；可定位，不反复toast |
| 确认源CRS缺失 | 这份资料缺少源坐标系 | 补充定位依据；仅阻断需要定位的分析 |
| 附件无主影像 | 这是定位附件，请选择对应影像 | 补选主件；不称CSV方言错误 |
| 同名distance语义冲突 | 当前资料未匹配方案要求的距离指标 | 查看要求/重新绑定，不猜是哪种距离 |
| 真实评分方向缺失 | 指标“X”尚未设置评分方向 | 打开该指标的规则 |
| 源单位未知 | 指标“X”的原始单位尚未确认 | 查看来源/补充单位；不把目标单位反填 |
| 归档项目 | 项目“X”已归档 | 有权恢复或换项目 |
| 当前任务回收但项目活跃 | 研究“X”已回收 | 换任务/新建/有权恢复；不锁死整个项目 |
| 保存失败 | 更改尚未保存 | 重试/处理冲突；不自动消失或显示已保存 |
| 检查失败 | 检查未完成 | 重试，保留错误详情；不输出0项待处理当通过 |
| 显示失败但计算产物存在 | 结果已生成，地图显示失败 | 重试显示/查看成果；不重新计算 |
| 无独立业务验证 | 工程结果·未业务验证 | 成果工具条一次提示，详情可查，不每个步骤重复 |
| 当前成果与编辑配置不同 | 当前结果来自配置第N版 | 显示实际新旧身份和运行入口，不把“已保存”当“已更新成果” |

超时不直接宣称操作失败：能够查到操作ID时查询真实结果，避免重复导入/绑定/作业。重试使用原意图身份，用户主动复跑为新意图。修复入口也需服务器校验，不能依赖前端按钮可见性。

## 10. 布局与可访问性约束

- 简单空状态：一个必要标题、一句状态、一个主动作；不加“结果”“引用”“预检”“版本”四个空分区。
- 简单资料装配在面板首屏就看到输入和添加入口；不需要滚过一屏解释才操作。
- 正文继续约14px、紧凑表格36—40px行高；信息简化靠删除重复层级，不靠小字、CSS zoom或隐藏溢出。
- 普通字段不靠placeholder代替标签；必要错误关联具体输入；状态不只靠颜色或图标。
- 自动更新的关键状态可被辅助技术感知，不每次刷新强抢焦点或反复播报正常状态。
- 详情、提示和展开/关闭可用键盘；不能把完整限制只放鼠标hover。
- 关闭、切菜单、查看方法不修改任务内容；存在真实未保存风险才询问。
- 浏览一个方法时，不默认让无关的资料步骤与结果说明继续占据全部右侧。保留研究状态，而不是强制所有旧面板同时可见；用户明确固定的面板可保留并标清当前对象。

## 11. 后端保留规则与前端投影

本轮可按需完善现有接口的结构化状态/错误，但不另建一份数据库作为“UI真源”。建议视图通过现有资料、任务、检查和运行状态组合得到：当前编辑对象、相关输入、检查进度、当前问题、此步输出与可用动作。

“按钮不可用原因”“修复对象”“受影响动作”由实际能力/权限判断，不把任意后端长message直接塞进页面；未知错误保留可追踪编号和受保护技术详情，不能伪装成已知业务错误。

重用检查结果必须匹配固定数据和配置版本、方法及权限适用条件；过期即标需检查，异步响应携带请求上下文，不污染新任务。权限撤销后清除无权显示内容，不能为了保持研究现场继续展示秘密。

正常状态收敛，以下信息不能被整体删掉：真实失败、必要科学缺口、样本/全域范围、转换损失、未知单位/定位、方法适用问题、历史结果版本、保存失败、权限限制、最终结果尚未独立验证。它们出现于需要该信息的对象和动作，不铺在无关页面。

工程缺适配器或算法属于未实现；用户端可清楚标不可用，验收记录必须写未实现/FAIL，不伪装成“资料缺失”。
